### 🔴 新增护栏：确定性卡死 run 的"投毒"机制
**问题**：种子是 `22260912+1000×题号+run` 固定的 ⇒ **卡死的 run 重驱必定再卡**。
旧 driver 每轮都会重驱同一批缺口，一个卡死 run 会在一个槽位上反复烧满 `SLICE_TIMEOUT`
（8 轮 × 4 h），整个扫描永远收敛不了。

**做法**（新增 `mark_poison.py`，`missing_runs.py` 与 `driver.sh` 配套改动）：
1. driver 给每个切片记录退出码日志 `logs/<KEY>/rc_part<NN>.txt`，行格式 `<runs>|<rc>`；
2. `timeout` 杀进程返回 **124**；同一片**同一个 run 列表**被 124 杀掉 **≥ `MAX_SLICE_FAILS`（默认 2）次**
   → 调 `mark_poison.py`；
3. `mark_poison.py` 的判据很干净：切片按顺序执行且每个完成的 run 都原子落盘，
   所以**列表里第一个磁盘上没有对应 .mat 的 run 就是卡死的那个**（它后面的 run 只是没轮到）。
   只把这一个 run 写进 `logs/<KEY>/poison.txt`（`<part>|<run>`），其余尾部照常重驱；
4. `missing_runs.py` 读 `FE500_POISON` 跳过这些对；driver 启动时会把已有的 poison 列表打出来，
   收尾时把 `poisoned=<n>` 记进日志。**验收脚本会把这些缺口报成 MISSING，不会被悄悄吞掉。**

要求"2 次"是为了防止把**只是慢**的 run 误判成卡死。

## 00:05–00:15 用户反馈"CPU 利用率还是很低" → 定位并修掉**启动节流**（第三次重启）

### 诊断（实测，不是猜）
采样 6 次：**只有 2–3 个 MATLAB 在跑**（上限 14），CPU ≈ 12–15%。日志显示切片启动被卡在
**固定每 22 s 一片**（`sleep 20` + 开销），而**一个 SSDE 切片只要 ~25 s** ⇒ 前一片刚跑完、
下一片还没启动，进程池永远填不满。
根因：`sleep 20` 是为"本机多进程同时**冷启动**会 ntdll 堆损坏"设的保守间隔，
但它对**切片时长 < 间隔**的算法（SSDE）变成了纯粹的吞吐限制器。

### 修复 1：冷/热分段节流
`LAUNCH_GAP=20`（每次 pass 的**前 `COLD_STARTS=4` 次**启动用，保护冷启动）、
`LAUNCH_GAP_WARM=5`（之后用）。危险的是**冷启动**，不是稳态。
效果：启动间隔 22 s → ~8 s，SSDE 两分钟内 149 → **256/320**，进程数 2–3 → 14。

### 修复 2：内存闸（比降 MAXJOBS 更好）
实测每 worker 占 0.6 GB（SSDE）~1.2 GB（patternnet/dacefit 类）；
本机 31.3 GB 总内存但 OS+应用已吃 ~16 GB，**基线空闲只有 16.8 GB**。
14 路跑到 REMO/PACDIS/HES 时可能开始换页——**换页风暴的代价远大于多两个槽位的收益**。
所以每次启动前检查 `MIN_FREE_MB=3500`，低于就 `wait -n` 等一个切片结束再启。
⇒ **池子会自己按内存缩容，内存够时保持 14**，不需要用户手调 MAXJOBS。
