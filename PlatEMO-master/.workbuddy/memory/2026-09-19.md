### ⚠️ 踩坑：MATLAB `jsonencode` 把二维 cell 按列主序压平
`T.cells = cellsT`（16×4 cell of char）经 `jsonencode` 变成**一维 64 元素字符串数组（列主序）**，
Python 侧 `cells[p][a]` 变成取字符串第 a 个**字符** ⇒ 数据行被写成单字符（F2='2'、G2='.'…），
**表头与计数行却完全正常，极隐蔽**。
修法：MATLAB 端 `arrayfun(@(p)strjoin(cellsT(p,:),'|'),1:nP,'UniformOutput',false)` 变成 1×nP 行字符串数组，Python 端 `split('|')` 还原。
**规则：MATLAB→JSON 传二维 cell 一律先 strjoin 成「每行一个字符串」，不要直接扔二维 cell。**
（另：改完 `cells` 结构后忘了同步修 MATLAB 里的 `fprintf` 打印循环，`tables(t).cells{p,pos}` 立刻报索引越界 —— 结构体字段换了表示形式，所有引用点都要一起改。）

## 20:46–21:30 — HES_EA_N100 死锁缺陷定位与 guard（当天最重要的发现）

### 症状
首次全量扫描 7 h 只产出 22/320，5 个 worker 各烧 ~40% CPU 但 6.5 h 零产出、日志停在 14:19。
杀掉后**串行复现**：DTLZ2/M20/run1 在初始化（33.33%）之后第一轮就挂死。

### 根因（分阶段 tic-toc + CSS 状态转储定位）
1. `HES_EA_N100.m` 每轮 `randperm(M,2)` 随机挑两个目标轴做 2-D 聚类。
2. **DTLZ2/DTLZ4 的几何结构：最小化目标 1 的解同时最小化目标 2**（θ1=π/2 的那个点），
   所以当随机对含 (1,2) 时，`NormObj` 里有一行在两个选定目标上**同时为 0**
   → `pdist2(...,'cosine')` 返回 NaN → 聚类 while 循环里那行的
   `ang(isnan(ang) & ~isinf(ClObj(:,1))) = pi` 兜底**没救回来**（已被赋值的行 pdist2(inf,·) 返回
   有限角 π/2 < π，孤儿行永远轮不到）→ 留下 `Cluster==0` 孤儿。
3. `CSS.m` 被要求选满 `searchN` 行，但孤儿行 `find(Cluster==i)` 永远找不到
   → `counter` 卡在 searchN-1 → 所有簇抽空后 `Pr = 0/0 = NaN` → `rand(1)<NaN` 恒 false
   → **`while counter < N` 死循环**（实测 10 万圈 counter=99/100 不动）。
4. 状态转储证据：`CSS start: rows=100 target=100 Cluster==0 count=1` →
   `pass 100000: counter=99/100 rows left=1 Cluster==0=1 Pr=[NaN×4]`。
   **这也解释了为什么当年 M=10/M20 都只跑出 DTLZ1 的 16 个文件** —— 就是挂死在 DTLZ2 后放弃的。
