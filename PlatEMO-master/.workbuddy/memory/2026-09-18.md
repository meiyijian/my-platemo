## DTLZ7 的 parpool 崩溃（重要教训）

给 `20目标\..._NoBatchDist` 补 IGDp 时，DTLZ7 反复把 MATLAB 进程搞崩，**四次并行尝试全部失败**：
5 worker+官方 IGDp / 6 worker+官方 IGDp / 6 worker+分块 IGDpFast / 4 worker+worker 自建 problem。
共同特征：**崩溃时没有任何异常** —— try/catch 抓不到、日志停在上一题、进程直接消失。

**根因**：`DTLZ7.GetOptimum` 用的是 `UniformPoint(N, obj.M-1, 'grid')`（**网格**模式），
网格点数随目标数**指数爆炸**：M=10 时 19683 点，**M=20 时 2^19 = 524288 点（83.9 MB）**；
而官方 `IGDp.m` 对每个参考点都 `repmat` 一次 300×20 临时矩阵
⇒ 单次 IGD+ 要 7–9 s，一个文件（30 快照）近 4 分钟。
（我先前说「七算法全量跑时 DTLZ7 只用 22 s」是**错的**，按实测成本根本不可能。）

**已验证有效的规避**：
- `IGDpFast.m`：参考点**分块（每块 2 万）向量化**，数学等价（实测 relDiff = 0，覆盖
  DTLZ7/M=20、WFG1/M=20、DTLZ1/M=10 三种），单次 7.38 → 4.43 s，**分配次数从 52 万降到 39 次**。
- **串行完全可行**：`ComputeDTLZ7Serial.m` 跑通 DTLZ7 run 1 的全部 30 快照（1.4 分钟，1.86–4.09 s/快照）。

**新坑（务必记住）：本机不要同时拉起多个 MATLAB 实例**。改用「4 个独立进程各跑 5 个 run」时，
**4 个进程日志全部为空、无一产生输出**，即**启动阶段就失败**（单个实例启动一直正常）。
⇒ 多进程分片必须串行启动或降低并发，「开最大进程」在本机行不通。

**未完成**：`20目标\..._NoBatchDist` 的 DTLZ7 仍缺 IGDp（产物只到 DTLZ1–6），
其 WFG1/WFG9 也只有 IGD、没有 IGDp。下一步走串行 DTLZ7（约 28 分钟）。

## 新建两个消融变体：REMO_noBatchDict_noCDIS / REMO_noBatchDict_noPAQC

- **BatchDict = BatchDist**（用户笔误，全库无 BatchDict 概念）；两变体都继承 NoBatchDist 的「无批内距离」。

**产物**（均放 `Algorithms\Multi-objective optimization\`，checkcode 全过）：

  RepresentativeBasedClassification) + explore(NoBatchDistWeightedBatchSelection) +
  **explore-only 的 DiversifiedInfillSelection**（新写，删 switch+indicator 分支，model_select 恒 weighted_mean）。

## 提交推送 + .git 对象库损坏事故（重要教训）

commit **7fb589d** 已推送并核实（远程 master = 7fb589d，两个变体 + memory + .gitignore）。

**事故**：push 报 non-fast-forward（本地落后），尝试 `rebase --autostash --onto` 时崩溃：
`1c437003... is not a valid object` + `Cannot autostash` + `bad object HEAD`。
根因：**rebase --autostash 在 Windows + PowerShell 下把 `.git/objects/pack/*.pack` 删掉了**
（只剩 .idx），大量 blob/commit 对象丢失，master 与 origin/master 都指向无效对象。
（工作区文件全程未丢，只有 .git 损坏。）

**恢复**：
1. 重新 clone 远程到 `_clone_new`——远程 master 已含之前会话的 memory/run_scripts/论文主表
   （是另一路 merge 进来的 `fa052c9`），故本地与远程**净差异只有**两个算法 + memory 追加 + .gitignore。
2. 把两个算法目录 + memory + .gitignore 复制进新 clone → commit（7fb589d）→ push（fast-forward 成功）。
3. 用新 clone 的 `.git` 替换旧目录损坏的 `.git`（旧 .git 备份为 `.git.corrupt.bak`；`_clone_new` 暂留作兜底）。

**教训（写死）**：
- **Windows 上严禁 `rebase --autostash`**（会删 pack 文件）。要 rebase 先手动 `git stash` 或确保工作区干净。
- 远程 master 有**并行写者**（另一会话/自动化在 push），push 前先 `ls-remote` 核实；
  non-fast-forward 时优先「重新 clone + 搬改动」，不要 rebase。
- PowerShell 5.1 把 git 的 stderr 进度当 NativeCommandError，但**不影响命令本身**；
  fetch 的 `-> origin/master` 进度 ≠ ref 真更新，一律以 `rev-parse`/`ls-remote` 为准。
