## 23:07 NBGGP（NoBatchDist Good-group Precision）并行启动

用户点名跑 `PlatEMO\Experiments\REMO_UniformMix_Pruned_Weighted_Lambdat030_NoBatchDist_GoodGroupPrecision`。

### 协议（读自 README + `NBGGPProtocol.m`）
- **formal = DTLZ2 / DTLZ4 / DTLZ5 / DTLZ7 × M=10/20 × runs 1–20 = 160 jobs**
- N=100, requested D=30, **maxFE=300**, gmax=3000；参数 `{pMix,rGood,qKeep,nMax}={0.50,0.25,0.70,6}`
- 种子用历史 GGP 公式 `problemIndex*10000 + M*100 + run`（DTLZ2=1, DTLZ4=2, DTLZ7=3, DTLZ5=7）
- 结果 → `results\raw\formal\<题>\M<M>\`；`finish_NBGGP` 在 160/160 通过后写 `FORMAL_COMPLETE.txt`
- **`verify_NBGGP` 是硬门**（`equivalence_passed.txt` 必须为 PASS），本次实测 3 个 case 全 PASS（39 s）

### ⚠️ 关键发现：**原 runner 是串行的**
`run_NoBatchDistGoodGroupPrecision.m` 里是 `for jobIndex = 1:numel(jobs)` **逐个跑，完全没有 parpool**。
**实测单跑 212–223 s，且 M=10 与 M=20 几乎一样慢**（212 vs 223）⇒ 160 个串行要 **9.4 小时**。

### 解法：并行 wrapper（不动原脚本）
`\.workbuddy\run_scripts\RunNBGGPParallel.m` —— 用 `parfeval` 把
**(題 × M × run 段)** 分成 **16 个子集**（8 组合 × 2 段，每段 10 跑），
每个子集独立调一次原 runner。安全性：每个 job 都是「临时文件 + movefile 原子提交」，
各次调用各写自己的 manifest（文件名带 pid），子集之间不会互相污染；已存在的 job 会校验后跳过。
12 workers 启动，ETA 约 **40–50 min**（原来串行 9.4 h）。
日志 `_nbggp_parallel.log`。**跑完再执行 `finish_NBGGP`**。

### 踩坑
- PowerShell 传 MATLAB 字符串：`""DTLZ2""` 会被 PS 解析坏（报「函数或变量 'DTLZ2' 无法识别」）。
  **一律用 MATLAB 单引号** `'DTLZ2'`，在 PS 的双引号里是安全的。
