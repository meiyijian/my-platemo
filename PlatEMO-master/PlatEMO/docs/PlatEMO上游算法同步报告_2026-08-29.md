## 二、关键风险与处理：同名 helper 遮蔽

### 问题

`platemo.m` 使用 `addpath(genpath(cd))` 把整个目录树加到 MATLAB 搜索路径。MATLAB 的函数解析规则是：

1. 按**文件名**查找（不是文件内部函数名，例如 `CrowdingDistance.m` 里定义的其实是 `CrowdDis`）
2. **不看调用者所在目录**，只看全局路径顺序
3. 路径顺序由 `genpath` 的目录遍历顺序决定，即字典序

因此，直接把 35 个新目录复制进来，会有 15 个函数名被新增目录抢占，改变既有代码的解析结果。

### 最危险的一例

| 文件 | 签名 |
|------|------|
| 新增 `MaOEA-HAP/Shape_Estimate.m` | `(Population, N, z, znad)` — 四参数 |
| 既有 `PIEA` / `REMO_new2_AdaMaO` 等的调用 | `Shape_Estimate(Population, N)` — 两参数 |

`MaOEA-HAP` 字典序在 `PIEA` 之前，抢占后会波及 **PIEA、PIEA_R、PIMD、REMO_SDE、REMO_global_SDE、REMO_new2_AdaMaO、REMO_new2_AdaMaO_Simple(A)、REMO_new2_PIEA3/4/5**，直接触发参数不足的运行时错误。

### 解决方案：private 隔离

把新增目录中**与既有目录重名的 .m 文件**移入该目录自己的 `private/` 子目录：

- `genpath` 会跳过名为 `private` 的目录 → 这些文件不进入全局路径，对既有代码**零影响**
- MATLAB 中 `private/` 对父目录中的函数具有**最高优先级** → 新增算法仍能正确调用自己的 helper
- 主类文件（`classdef ... < ALGORITHM`）保留在顶层 → GUI 的 `readList2`（同样走 genpath）仍能发现新算法

### 处理结果

| 指标 | 数值 |
|------|------|
| 隔离文件总数 | 127 |
| 隔离后新增目录在全局路径上的重名文件数 | **0** |
| 被隔离文件最多的算法 | NeuroEA(8)、KLEA(8)、MOEA-D-EGO-CEI(7)、PEA/PEAplus/TSPP/MaO-TSPP/AMG-PSL(6) |

## 三、使用建议

1. 新算法可直接通过 GUI 或 `platemo('algorithm',@XXX,...)` 调用
2. 若某新增算法运行时报「输入参数数目不足」，大概率是它依赖的通用 helper（如 `EnvironmentalSelection`、`CalFitness`）被更靠前的目录遮蔽——这是 PlatEMO 上游本身就存在的问题，不是同步引入的
3. 后续再次同步上游时，请沿用本报告第二节的 private 隔离流程，不要跳过
