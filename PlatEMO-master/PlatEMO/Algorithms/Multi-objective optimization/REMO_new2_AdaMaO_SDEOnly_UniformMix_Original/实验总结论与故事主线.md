## 1. 一句话总结

在两个新增模块中，**混合 PBI 分类模块（HPC）是承重模块，候选解路由模块的净效应为零**。而 HPC 真正起作用的成分是**监督标签的表征粒度（连续裕量与二值阈值并存）**，不是「两个视图几何互补」，也不是「按预算动态调权」——后两条都已被机制层实验否掉。

## 3. 能站住的五条结论

### 结论 1：端到端性能优于继承基线与代表性对照（B 级）

`FE500/候选解模块改动最终版/十目标.xlsx`，DTLZ1–7 与 WFG1–9 共 16 个问题，M=10，D=30，N=100，FE=500，指标为 IGD。参照列为本算法：

| 对照算法 | 胜/负/平 |
|---|---|
| REMO | 2/10/4 |
| PIEA | 5/7/4 |
| MCEAD | 4/11/1 |
| R2AEA | 5/7/4 |
| HES_EA | 4/8/4 |
| PCSAEA | 0/15/1 |

对继承基线 REMO 净胜 8 个问题，对全部 6 个对照都是净胜。这是目前最接近论文主表的一张表。

**两点必须说清**：一是该表参照列写的是 `REMO_new2_AdaMaO_SDEOnly_UniformMix`，不是 `_Original`；关系对实验已证明这两者统计不可区分（0/0/16），但正式主表仍应统一到冻结的 `_Original` 类名重跑。二是该表缺 seed、代码 hash 与多重校正，只能作趋势。

### 结论 2：HPC 是承重模块，候选解模块主要贡献是打平（B 级）

六臂消融，FE=300，指标 IGD。以完整算法为参照：

| 拆掉的部分 | M=10（参照 `full (k=15)`） | M=20（参照 `full (k=30)`） |
|---|---|---|
| 去掉 HPC（= REMO+candidate） | 2/9/5 | 3/9/4 |
| 去掉候选解模块（= REMO+HPC） | 1/3/12 | 1/3/12 |

去掉 HPC 在两个目标数下都净输 6–9 个问题；去掉候选解模块则有 12/16 个问题打平，净输仅 2 个。**两个模块的重要性不在同一量级。**

HPC 的增益集中在 **WFG4–WFG9**（连续、多模、非分离）。**WFG3 方向相反**——去掉 HPC 反而更好，与后文第 5 节的失效边界一致。

### 结论 3：锚点数与表征是交互效应，不可相加（B 级，且是最有说服力的一条负结果）

这条最反直觉，也最值得放在论文里。**单独把参考方向数从 k=6 提到 k_eff=⌈1.5M⌉ 是有害的**：

| 臂 | 相对 `full` 的胜/负/平 |
|---|---|
| REMO（原始，k=6） | 2/9/5（M=10）；2/8/6（M=20） |
| REMO (k=15) | **1/10/5**（M=10，最差臂） |
| REMO (k=30) | **1/11/4**（M=20，最差臂） |

只提锚点数的臂，在两个目标数下都**比原始 REMO 更差**。但换成以 `REMO(k_eff)` 为参照，再加上 HPC：

| 加入的部分 | M=10（参照 `REMO (k=15)`） | M=20（参照 `REMO (k=30)`） |
|---|---|---|
| + HPC | **8/1/7** | **11/2/3** |
| + HPC + 候选模块（完整） | 10/1/5 | 11/1/4 |

同一个改动，在原始表征下有害、在混合表征下大幅有益。**增益来自表征方式，不来自锚点数量**；提高 k_eff 只是为混合表征提供了必要的分辨率。

论文里提 k_eff=⌈1.5M⌉ 时应给两个与代码对应的理由，而不是「锚点越多越好」：REMO 的 `RefSelect.m` 相对 RSEA 原设计只保留 1 个极值解（RSEA 保留 m 个），且标签生成时网格分辨率降到 `ceil(√k)`（k=6 时是 3×3=9 格去划分 10 维前沿）。提高 k_eff 是同时恢复边界覆盖和网格分辨率。

### 结论 4：二值阈值标签是必要成分，全连续化显著更差（B 级，新证据）

这是本次汇总中最重要的新发现，之前没有被单独提炼过。`混合PBI/` 目录把标签整个换成连续双 PBI 得分（`DualPBICont` 及其 Weighted / Unweighted / Filter 三个变体），16 问题，M=10，IGD：

| 参照列 | 当前生产标签（UniformMix）相对它的胜/负/平 |
|---|---|
| `DualPBICont` | **10/0/6** |
| `DualPBICont_Weighted` | **10/1/5** |
| `DualPBICont_Unweighted` | **9/0/7** |
| `DualPBICont_Filter` | **11/0/5** |

反向看同一组数据（`一动一静/十目标一动一静.xlsx`，参照列为 UniformMix），四个连续化变体各自 1/13/2——**13/16 个问题输给现行标签，一个问题都没赢过两个以上**。典型数值如 DTLZ2 上 1.09 对 1.32–1.45，DTLZ5 上 0.652 对 0.742–0.820。

含义很直接：**「把二值阈值换成更精细的连续分数」这个看起来更合理的方向是错的**。二值阈值不是实现上的粗糙妥协，而是有效成分。这正好支撑「表征粒度互补」而不是「几何互补」的叙事。

### 结论 5：两个视图确实非冗余（A 级）

双 PBI 互补性实验（250 次 replay，完整性门槛 `FINAL_INTEGRITY_GATE=PASS`，250/250 重放等价，最大绝对差 0）给出：

- 方向视图 V 与锚点裕量视图 A 的 Top-25% 集合平均 **Jaccard 仅 0.2326**；两侧各平均有 15.85/25 个独有候选，约 **63.4% 不落在对方集合内**
- **双向独有真阳性在 40 个单元中有 33 个通过 Holm 校正**（原始 p≤0.05 为 34/40）；1000 个 run-stage 中 V 独有出现 928 次、A 独有 891 次，`UniqueTPShare` 均值 0.815

也就是说，「两个视图看到的不是同一批解」这一点证据很硬。但这**不等于融合有增益**——见下一节第 3 条。

配套的 Good-Group Precision 正式实验（250 job，10/10 单元完整）在 `population_final` 真值下，`score_hybrid` 对 `score_v` 为 41 胜/14 负/65 不显著，对 `anchor_margin` 为 39/33/48。注意这里 n=120 是「10 个 Problem–M × 4 个 Stage × 3 个指标」的检验单元数，**不是运行次数**，所以这是关联证据，不是因果证据。

## 4. 不能站住的六条

这一节是论文能否经受审稿的关键。诚实写出来比藏起来强，而且其中几条本身就是可发表的负结果。

### 4.1 候选解路由模块净效应为零（三条独立证据）

| 证据来源 | 结果 |
|---|---|
| 六臂消融（FE=300） | 去掉该模块，M=10 与 M=20 都是 1/3/12，**12/16 打平** |
| 候选价值探针 CVP（M=20，200 job） | V4 对强基线 V1（累积池 top-6）**Wilcoxon p=0.375** |
| 置信度探针候选级 | 候选边际 IGD+ 增益 Q5−Q1 = +0.024，CI [−0.050, +0.122]，**跨零** |

CVP 还给出两条更细的否证：两个分支单独都不成立——explore 分支 p=0.847 完全无效（虽然批内分散度确实升到 2.03，说明开关接通了但没用），indicator 分支 **有害**（p=0.027 差于基线，在 DTLZ7 上 10/10 全败）。UniformMix 混合的作用是**把 indicator 分支的害稀释一半，不是把两个分支的好处叠加**。

而两个专门为该模块设计的实验都还没有结果：CMC 只跑完 9/24 个 Stage 0 pilot 任务（`stage1_counterfactual`、`stage2_screening`、`stage3_formal` 目录根本不存在，8 个门控 CSV 只产出 1 个），CPR 一个 job 都没跑。

**结论**：`pMix=0.5` 的 UniformMix 应写成**稳健的路由控制策略**，不能包装成独立创新点。

### 4.2 关系对构造的三个变体完全零效应

`关系对实验/` 8 张表，16 问题 × M=10/20。Original / Weighted / Curriculum / 自适应 四个变体两两相比，几乎全部是 **0/0/16**（个别单元格出现 1/0/15 或 1/1/14）。八张表交叉核对，同一算法在不同表里的数值完全一致，说明不是统计力不足，而是**这条方向确实没有效果**。这条路可以直接关闭，不必再投预算。

### 4.3 动态融合并不优于「逐 run 更好的那个单视图」

这是与结论 5 配对的负面部分，也是目前叙事上最大的裂缝：

- 严格融合的交并检验（IUT）：原始 p≤0.05 为 8/40，**Holm 校正后只剩 1/40**（唯一通过的是 WFG3-M20-S1）
- `Delta_best` 均值 **−0.02448**（Hybrid 减去每个 run 内 V/A 中较优者）；1000 个 run-stage 中 310 胜/106 平/**584 负**，胜率仅 0.363
- 问题族反转：DTLZ 的 `Delta_best` = −0.00805，WFG 为 **−0.04913**，WFG7 的 8/8 个单元全为负
- Stage3 独立给出同向结果：WFG 族 `L3 − max(L1,L2)` = **−0.0516，Holm p=1e-6**，CI [−0.0607, −0.0427]

**但有一个重要的辩护，必须同时写清**：`max(V,A)` 是逐 run 事后选优，属于 oracle（先知）基线，实际部署时无法知道该用哪一个，所以「输给 oracle」本身不构成致命问题。总体上也确实没有单视图占优（V 对 A 为 33 胜/40 负/47 不显著，基本持平）。

真正需要回答的是一个更弱、但可部署的问题：**在 WFG 族上「恒用 V」是否比动态 Hybrid 更好？** 如果是，那么正确的算法就该是分族固定权重，而不是动态调度。这项检验用现有 CSV 就能算完，零新增预算，应当作为第一优先。

### 4.4 时间调度未被证明必要

Stage2 决策为 `PASS_TO_STAGE3`，但附带 `SCHEDULE_REDUNDANT` 告警，含义是「仅按 FE 进度切换权重可能没有额外价值」。DPC 的最终判定里，「动态权重因果优势」一栏写的是 **NOT TESTED**。

因此 `α = 1 − FE/maxFE` 这个形式（在函数形式上正好是 RSEA 原始 `r = 1−(t/tmax)²` 被 REMO 冻结成常数 0.1 之后的复原）目前只能作为**设计动机**写，不能声称已被验证。要声称调度必要，必须做 Dynamic / Fixed(α=0.5) / Reverse 三臂的正式 30 次运行比较。

### 4.5 标签的独立 PF 效用尚未确立

Stage3 决策 `INSUFFICIENT_REFERENCE_STABILITY`，阻塞点精确定位在 **DTLZ7_M10**：在参考集加密到 R=16384 后，该单元两个 behavior 仍不达标（AnchorNative 的 SpearmanLOO=0.9454、OracleJaccard=0.9121；Hybrid 为 0.9660、0.9385；门槛是 0.95 与 0.90）。20 个有数据的单元里 18 个通过，DTLZ7_M20 在同样密度下反而通过（0.9778 / 0.9856）。

在这条修好之前，**不能写「Hybrid 标签具有独立于标签公式的 PF 外部效用」**。

### 4.6 CSR 作为机制指标已被证伪

候选存活率（CSR, Candidate Survival Rate）与 IGD 的臂层面秩相关只有 +0.20（p=0.40），而 oracle 指标是 +0.71 / +0.63（显著）。原因是 **CSR 与批内分散度负相关**（−0.31，p=6e-6；在 DTLZ7 上达 −0.83）：`RefSelect` 保留靠近当前种群的解，批次挑得越挤 CSR 越高，冗余解一起存活。CSR 最高的两个臂恰好落在 IGD 的两端。

这是一条干净的方法学负结果，比「模块有效」更容易发表，建议单独成段。同时注意 oracle 指标的解读约束：无一臂命中率超过随机基线 0.0150（=6/400），GainRatio 均值仅 0.059–0.123，所以**只报 regret 式的 GainRatio，不要单报 HitRate**。

## 5. WFG3：一条反复出现的失效边界

WFG3 在四组彼此独立的实验里都反向，这不是噪声：

| 实验 | WFG3 上的表现 |
|---|---|
| 两模块消融 | 去掉 HPC 反而更好（唯一反向的问题） |
| 置信度探针 v2 | 错误率 Q5−Q1 为 **+7.6pp**（其他问题为 −12 至 −41pp），AUROC 0.464；三批独立证据一致落在 0.46–0.47 |
| DPC 严格融合 | Holm 后唯一通过的单元恰好是 WFG3-M20（方向相反的孤例） |
| CVP 累积池 | 池化在 WFG3 上 0/10 全败，p=0.002 |

几何解释是清楚的：WFG3 是退化前沿，本征维远小于 M，RSEA 式的径向 2D 投影会把前沿压进很小的区域，网格出现大量空格加少数过挤，多样性信号坍塌。

**处理方式**：写成 known limitation（已知适用边界），并给出几何原因。但要注意一条辩护材料**不成立**——CVP 显示 V0/V1 共享同一套 HPC 标签而 V1 在 WFG3 上 10/10 更差，说明**池化本身就在 WFG3 退化，不能把 WFG3 的问题全部归因于 HPC**。

## 6. 必须先修的数据问题

写论文或投稿前，以下四条会直接被审稿人抓住：

1. **4 个 M=20 文件里 WFG4 行的 M 列写的是 10**（已在 `REMO_Candicate_20.xlsx`、`REMO_HPC_20.xlsx` 等确认）。且该行 IGD 量级约 8.4，落在 M=10 的区间（6–8.2）而非 M=20 的区间（20+）。**这一行很可能实际是 M=10 的运行**，需重跑或修正。

## 7. 推荐的故事主线

**主线一句话：在有限真实评价预算下，关系学习代理的瓶颈不在关系模型本身，而在给它的监督标签。有效的修复是让两种粒度的质量表征并存——连续裕量与二值阈值——而不是把标签做得更精细，也不是引入几何互补。**··

下面按五段展开。每段都对应上文的具体证据，不含未验证的表述。

### 第一段：问题定位——标签在高目标数下失真

REMO 用一个标量把种群划成好组和坏组，再用关系对训练分类网络。这套参考解机制继承自 RSEA，但继承时发生了四处偏离，都能在 `RefSelect.m` 中逐行核对：时间衰减因子 `r` 被冻结成常数 0.1（RSEA 原本从 1 衰减到 0，0.1 对应 t/tmax≈0.95，即从第一代起就永久处在末期的多样性主导状态）；收敛标量 `Con` 从 L2 范数改成 L1；极值解保留从 RSEA 的 m 个降到 1 个；标签生成时的网格分辨率从 `√N` 降到 `ceil(√k)`。

后两条的后果在 M 变大时被放大：M=10 时 RSEA 会留 10 个极值解，REMO 只留 1 个，边界覆盖的保证被破坏；k=6 时网格只有 3×3=9 格，要去划分一个 10 维前沿。ObjectiveDifficulty 探针给出的独立旁证是各目标分量对好坏判定的贡献显著不均匀，且随 M 恶化。

**这一段的作用是把研究问题落在「标签」上，而不是落在「网络结构」或「候选生成」上。** 这也解释了为什么本文不重复 REMO 的五种网络结构搜索。

### 第二段：第一次修复失败——补分辨率单独做没有用

最自然的想法是把参考方向数提上去，恢复边界覆盖和网格分辨率。实验结果是**这样做反而更差**：k=15 是 M=10 下最差的臂，k=30 是 M=20 下最差的臂，两者都差于原始 REMO（结论 3）。

这一段是主线的转折点，也是全部实验里最有说服力的一条。它说明分辨率不足只是表象：**在原有的单标量阈值表征下，更多的参考方向只会制造更多噪声标签。** 必须同时改表征，两者是交互效应，不能相加。

### 第三段：正确的修复——两种表征粒度并存

HPC 让两个成分同时进入监督信号：`score_hybrid = α·score_v + (1−α)·label_dyn`。其中 `score_v` 是学习到的方向场上的连续 PBI 裕量，承担分布与方向侧；`label_dyn` 是锚点上的二值阈值标签，承担相对收敛侧。

有三条互相独立的证据支持这个成分划分：

一是**去掉 HPC 就掉性能**（2/9/5 与 3/9/4），而在匹配了 k_eff 的对照下加入 HPC 得到 8/1/7 与 11/2/3（结论 2、3）。

二是**把二值阈值换成连续分数会显著变差**（13/16 输，结论 4）。这一条最关键，因为它直接排除了「连续化只是精细化」的解释：如果两个成分的价值在于同一件事做得更细，全连续化应该更好或至少持平，实测是大幅变差。所以二值阈值提供的是**另一种**信息，不是同一种信息的粗糙版本。

三是**两个视图的 Top-25% 集合 Jaccard 只有 0.2326，63.4% 互不重叠，双向独有真阳性在 33/40 个单元显著**（结论 5）。

**这一段的措辞要点：说「表征粒度互补」，不要说「几何互补」。** 几何互补是证不出来的——`score_v` 与 `label_dyn` 都是同一 m 维空间、同一种群派生方向上的 PBI 族标量，几何上没有本质差异。差异在于一个是连续裕量、一个是二值阈值，即质量表征层面。之前反复尝试证明几何互补而失败，原因就在这里。

### 第四段：诚实划定边界——融合有效，但「动态最优」不成立

必须主动写清三件事，否则会被审稿人当成掩盖：

融合的**强主张不成立**：严格融合优势 Holm 后只有 1/40，`Delta_best` 均值为 −0.024，WFG 族 Stage3 给出 −0.0516（Holm p=1e-6）。同时给出辩护——`max(V,A)` 是逐 run 事后选优的 oracle 基线，不可部署，而总体上也没有哪个单视图占优（V 对 A 为 33/40/47）。

**调度未被验证**：Stage2 的 `SCHEDULE_REDUNDANT` 与 DPC 的 NOT TESTED 都指向同一个缺口。`α = 1−FE/maxFE` 只能作为设计动机（它在函数形式上复原了 RSEA 被冻结的 `r`），不能作为已验证的贡献。

**独立效用未确立**：Stage3 被 DTLZ7_M10 阻断。

把这三条写进论文，正确的主张就收缩成一句可辩护的话：**两种表征粒度并存对最终优化性能有正向作用；至于用固定权重还是按预算调权，当前证据不足以区分。** 这个主张比原来弱，但站得住，而且留下了明确的后续工作。

### 第五段：模块降级——一个承重模块加一项工程稳健化

候选路由模块三条独立证据都指向零效应，两个专门实验都还没有结果。把它写成**稳健的路由控制策略**（在指标代理可用时按固定概率在两条候选路由间选择，避免任一条单独失效），而不是第二个创新点。

这样处理的好处是论文反而更干净：**一个承重的机制贡献（标签表征），加一项工程稳健化（路由控制），加两条方法学负结果（CSR 被证伪、锚点数与表征不可相加）。** 三个都是真的，比四个半真的强。

### 主线与现有证据链的对应

```
标签在高 M 下失真（代码事实 + ObjectiveDifficulty）
        │
        ├─ 只补分辨率 → 更差            ← 结论 3（反直觉负结果）
        │
        └─ 补分辨率 + 换表征 → 大幅变好  ← 结论 2、3
                  │
                  ├─ 二值阈值必要        ← 结论 4（全连续化更差）
                  ├─ 两视图非冗余        ← 结论 5（Jaccard 0.2326）
                  └─ 但融合不优于 oracle 单视图、调度冗余  ← 4.3、4.4
                            │
                            └─ 主张收缩为「并存有效，权重形式待定」
候选路由 → 净效应为零 → 降级为稳健控制    ← 4.1
WFG3 退化前沿 → 已知失效边界              ← 第 5 节
```

## 8. 主线还缺什么

按这条主线写论文，缺口按优先级排列如下。前三项都是**零新增真实评价预算**的分析工作。

| 优先级 | 工作 | 成本 | 决定什么 |
|---|---|---|---|
| **P0** | 用现有 DPC 的 CSV 检验「WFG 族恒用 V」是否优于动态 Hybrid | 零成本，纯分析 | 决定权重写成分族固定还是动态；这是第四段能否收紧的关键 |
| **P0** | indicator 代理的 holdout Kendall τ | 零成本 | 解释 CVP 里 indicator 分支为何**有系统性偏差**（它把批内分散度压到最低 1.03，不是随机重排） |
| **P0** | 修 Stage3 参考集稳定性（DTLZ7_M10） | 0 新 FE | 决定「独立 PF 效用」这句话能不能写 |
| **P0** | 修第 6 节四条数据问题 | 低 | 投稿前必须 |
| **P1** | 关系模型的 solution-disjoint 泛化检验 | 约 2700 次网络训练 | 现有 `p_err` 按关系对随机拆分，同一基础解可能跨训练/测试集，不是可靠泛化证据 |
| **P1** | 标签三臂正式比较：Dynamic / Fixed(α=0.5) / Reverse，30 次运行 | 约 600 job | 唯一能证明调度必要性的实验 |
| **P1** | 主性能表统一到 `_Original` 冻结类名，扩到 M=10/20 × 30 次运行 | 视对照数量而定 | 结论 1 从 B 级升到 A 级 |
| **P2** | 运行时间、内存与失败率审计 | 嵌入上述 job | 算法含关系网络、SDE-SVR、K-means 方向构造，只报 IGD 不足以说明代价可接受 |
| **P2** | DTLZ7 与 WFG3 的 M=10 补跑 | 中 | CVP 目前只有 M=20 |

CMC 与 CPR 建议**暂不启动**。它们要回答的是候选模块的贡献，而该模块已有三条独立证据显示净效应为零；在主线已把它降级为工程稳健化之后，这两个实验的边际价值很低。CPR 的 formal 规划是 7680 个 job，投进去不划算。

## 9. 汇报时的取舍建议

组会或投稿汇报这批实验时，按下面的顺序讲最有力：

先讲**结论 3**（锚点数单独提升有害）。反直觉的负结果最能建立可信度，而且它自然引出「为什么必须改表征」。

接着讲**结论 4**（全连续化更差）。这条是新提炼出来的，直接把「表征粒度」这个说法从猜测变成有证据支持的判断，也是整条主线的支点。

然后讲**结论 2**（HPC 承重）和**结论 5**（非冗余），作为正面证据。

之后**主动讲 4.3 和 4.4**（融合的强主张不成立、调度冗余），并同时给出 oracle 基线的辩护。主动暴露裂缝比被问出来强，而且能自然过渡到 P0 的那项零成本检验。

最后讲**候选模块降级**和**WFG3 失效边界**。这两条都是把结论收窄，收窄之后剩下的东西才是可靠的。

不建议讲的：关系对四变体的零效应（除非被问到为什么关闭了这条线）、CSR 之外的机制指标细节、以及 CMC/CPR 的进度（它们没有结果，讲了只会引来「为什么不跑完」）。CSR 被证伪这一条可以单独讲，它是干净的方法学结果。
