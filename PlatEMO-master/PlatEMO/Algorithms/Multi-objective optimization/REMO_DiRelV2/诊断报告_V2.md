# REMO_DiRel 旧版失败原因复盘与 V2 改进对应

## 一、旧版失败的根本原因（按影响排序）

### 1. 关系标签链路从未真正实现 "subset Pareto + PBI"
**症状**：在 [REMO_DiRel.m:125](../REMO_DiRel/REMO_DiRel.m#L125) 中 `Catalog_F = GetOutput_PBI(PopObj, RefObj)` 先把单个解分成正/非正类，再在 [GetRelationPairsBudgeted.m:48-49](../REMO_DiRel/GetRelationPairsBudgeted.m#L48-L49) 中按 (正类, 非正类) 的组合标 +1 / -1，同类之间标 0。

**根本问题**：这样标的 pair 标签和"两个解 xa, xb 在子集 S 下谁更优"完全脱钩。例如：
- 解 a 在 S1={1,2} 上完全支配解 b，但只要它们都被 PBI 划成同一类，pair 标签就是 0
- 解 a 和 b 互不支配，但它们分属两类，pair 标签可能被强标 +1

**后果**：训练标签噪声很大，子目标 expert 学到的根本不是子目标关系，而是"PBI 分类器的近似映射"。这直接导致 ArbitratorScore 的预测不可靠。

**V2 修复**：`BuildPairBank_ParetoPBI`
- 阶段 1：对每个 pair 在 subset S 上做严格 Pareto 比较 → 直接拿到 +1/-1
- 阶段 2：互不支配的 pair 才用 PBI scalarizing value 比较，比较的是 `min_v PBI(F_norm, v)`，relDiff > tieMargin 标 +1
- 阶段 3：低 margin pair 给低权重 W ∈ [0.1, 1]，不强行高置信度训练
- 阶段 4：三类平衡采样，记录 stats（paretoRatio, lowMarginRate, labelHist）
- 同一对解在 S1/S2/Sfull 下标签可能不同 → 真正的 "multi-scale relation"

### 2. 单一 easy subset 太脆弱
**症状**：[REMO_DiRel.m:43-52](../REMO_DiRel/REMO_DiRel.m#L43-L52) 只构造一个 k_easy 子集，且 RefineEasySubset 用 `abs(rho) > 0.95` 检查冗余。

**根本问题**：
- 易子集选偏一次，整代 surrogate 就带偏
- `abs(rho) > 0.95` 把强负相关目标 (`rho ≈ -1`) 错误当作冗余删除 —— 强负相关恰恰是最有信息量的互补目标，不应该删

**V2 修复**：
- `BuildDifficultySubsets`：M≥5 时 K=3 (S1=M/3, S2=2M/3, Sfull=1:M)
- 冗余规则改为：仅 `rho > 0.95` （强正相关）才视为冗余；负相关绝对保留
- Sfull 必定存在（full expert 始终有数据）

### 3. acquisition 是 batch-relative 极端点筛选
**症状**：[ArbitratorScore.m:71-72](../REMO_DiRel/ArbitratorScore.m#L71-L72) `tildeS_F = minmaxNormScore(mu_F)` 把每代候选的 mu 归一化到 [0, 4]，然后 [ArbitratedSelection.m:71](../REMO_DiRel/ArbitratedSelection.m#L71) `scores > 3.9` 选解。

**根本问题**：
- 每代的 score 范围不同，3.9 阈值代际不可比
- 等价于 "本代分数最高的 2.5% 那一小撮"，倾向于选孤立极端点
- novelty 只看候选池内部 `pdist2(Cand, Cand)` ([ArbitratorScore.m:111](../REMO_DiRel/ArbitratorScore.m#L111))，不看 archive → 可能反复挑已经在 archive 附近的点

**V2 修复**：`ScoreCandidates_DiRel`
- 用 expected-win 直接基于 archive 上的 anchor，得到代际可比的 R(x) ∈ [-1, 1]
- 加入 archive-aware novelty (归一化决策空间距离)
- 加入 full-vs-subset disagreement 显式惩罚
- expert 权重 = globalRel × localConf，full expert 设最低权重下限 0.30
- SelectTopDiverse 用 greedy 距离约束，避免选出聚集点

### 4. 难度定义里 conflict 语义反转
**症状**：
- [ConflictDegree.m:73](../REMO_DiRel/ConflictDegree.m#L73) `conf(j) = mean(1 - |rho|)`
- [DifficultyProfiler.m:88](../REMO_DiRel/DifficultyProfiler.m#L88) `conflictDifficulty = 1 - confN`
- 等价于 `conflictDifficulty ∝ mean(|rho|)`，**和原始想表达的"冲突高 → 难度高"完全相反**

并且 spanScore 占总 difficulty 的 30%，让目标的"量纲尺度"主导了难度。

**V2 修复**：`DifficultyProfilerV2` 用 5 分量加权
- D_prog (0.35)：q10 改进率，archive 维度
- D_learn (0.25)：Kriging NRMSE（可选低频）
- D_conf (0.20)：**只用 `max(0, -rho)`** —— 负相关越强，冲突越高
- D_sens (0.15)：删除目标 j 前后 pair 标签翻转率
- D_span (0.05)：q90-q10，小权重
- + EMA 平滑保留历史趋势

### 5. 网络拓扑 bug
**症状**：[TrainDualScaleNet.m:145](../REMO_DiRel/TrainDualScaleNet.m#L145) 
```
hidden = max(4, min([ceil(xDim*1.25), xDim, ceil(xDim/2)], 24))
```
**根本问题**：`min([a, b, c], 24)` 在 MATLAB 中是按元素的 `[min(a,24), min(b,24), min(c,24)]`，返回 1×3 向量。`max(4, [...])` 同样按元素。最终 hidden 是 `1×3` 向量，patternnet(hidden) 会被解析为**三隐藏层网络**，与你设计的"单隐藏层 ≤24 节点"完全不符。

**V2 修复**：`TrainRelationExperts::chooseHidden` 强制返回 scalar `round(0.5*xDim)` 截断到 [8, 24]。

### 6. K_ens=3 + anchor 来源混淆
**症状**：
- K_ens=3 时方差估计自由度只有 2，逆方差权重噪声很大
- [ArbitratorScore.m:169-170](../REMO_DiRel/ArbitratorScore.m#L169-L170) anchor 来自 `Y_train==1` 和 `Y_train~=1`，而 `Y_train` 是 pair 标签 → 把 pair-level Y 当 individual-level 挑 anchor，语义错乱

**V2 修复**：
- K_ens=5 默认
- `SelectRelationAnchors` 从 archive 直接选 individual anchor：nondominated 部分作 elite，剩余作 diverse，目标空间均匀采样（farthest-first）

## 二、改进点与原始诊断对应表

| 原诊断条目 | V2 对应文件 | 验收要点 |
|---|---|---|
| (1) 标签噪声 | `BuildPairBank_ParetoPBI.m` | `PairBank.stats.paretoRatio` 应 > 0.4 (DTLZ 类); 同一 pair 在不同 subset 下 Y 不同 |
| (2) 单 subset 太脆弱 | `BuildDifficultySubsets.m` | `SubsetInfo.size` 应输出 K=3 个不同大小; `redundancyRemoved` 仅含正相关目标 |
| (3) [0,4] + 3.9 阈值 | `ScoreCandidates_DiRel.m` + `SelectTopDiverse.m` | 无 batch 内 minmax; scores 量纲一致; selected 真实改进率应可视 |
| (4) difficulty 反转 | `DifficultyProfilerV2.m` | `DiffState.Dconf` 在测试中：强负相关人为构造目标对其 Dconf 应升高 |
| (5) novelty 仅候选池内 | `ScoreCandidates_DiRel::archiveNovelty` | Nov(x) 来源是 archive 距离，可在 dbg 中输出 |
| (6) full vs subset 冲突无校准 | `ScoreCandidates_DiRel::Disagree` | sign(Rfull) × sign(Rsub) < 0 时 Disagree > 0 |
| (7) hidden 非标量 / K_ens 小 | `TrainRelationExperts::chooseHidden` | 强制 scalar; K_ens=5 |

## 三、smoke test 后的检查清单

按以下顺序看 Diag 数据：

1. **Diag.labelHist**：三类标签是否大致 1:1:1 分布。如果某 expert 90% 是 0 类，说明 PBI fallback 路径太松，可能要降 tieMargin。
2. **Diag.expertValErr**：每个 expert 的 validation error 应 < 0.45 (3 类基线 0.67)。如果 full expert 始终 > 0.5 但 subset 较低，说明在该 M 下 full 难学，正常；反之要查 pair 平衡。
3. **Diag.scoreStats** 第 2-4 行：mean U, mean Nov, mean Disagree 应有明显代际变化，不能全部恒为 0 / 1。
4. **Diag.archiveMinObjs**：每个目标历史最优是否在持续下降。如果有目标长期停滞，可加大 D_prog 权重。

## 五、若 smoke test V2 仍不如 REMO，按这个顺序排查

1. 看 `Diag.expertValErr` —— 如果训练就没学好（>0.5），说明 pair 数太少或 hidden 设错。增 `pairMaxPerExpert` 到 8000 或检查 chooseHidden 返回。
2. 看 `Diag.labelHist` —— 如果 +1/-1 比例 < 5%，说明 Pareto 严格支配几乎不存在（high-M 常见），需让 tieMargin 更小让更多 pair 进入 ±1。
3. 看 `Diag.scoreStats[1]` (mean weightedR) 是否随代上升 —— 不上升说明 acquisition 没有真正区分好坏。
4. 看 `Diag.expertValid` —— 是否有 expert 长期 invalid。若是，可降 `minTrainPairs` 阈值。
5. 看 `Diag.subsetSizes` —— 是否退化为全 M（说明 difficulty 没拉开差距）。
6. 单独跑 `A_singleSubset` ablation，若它和 A2 性能差不多，说明多 subset 没在帮忙，需检查 PairBank 在不同 subset 下标签确实不同。
