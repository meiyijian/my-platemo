🧠 REMO算法详解

Relation learning and prediction for Expensive Multiobjective Optimization
一种基于关系学习的昂贵多目标优化方法

📅 2022年发表 🎯 多/超多目标优化 📊 实数优化 ⚡ 昂贵问题

📖 一、算法概述

1.1 什么是REMO？

REMO（Relation learning for Expensive Multiobjective Optimization）是一种专门解决昂贵多目标优化问题的智能算法。

💡 什么是"昂贵"优化问题？

想象你要设计一架飞机，每次评估设计方案需要运行一次完整的CFD仿真（流体力学计算），一次仿真可能需要几小时甚至几天。这就是"昂贵"问题——每次评估都要付出巨大代价。

核心挑战：如何在有限的评估次数内，找到最好的设计方案？

1.2 核心思想：关系学习

传统方法直接预测"这个解好不好"，而REMO换个思路：

🎯 关系学习的妙处

不预测绝对好坏，而是预测"两个解谁更好"（相对关系）。

就像考试不预测分数，而是预测"A同学比B同学考得好还是差"——这种比较更容易判断！

✅ 优点

  • 不需要知道真实的目标函数值
  • 只需要比较两个解的优劣关系
  • 关系标签更容易获取和学习
  • 对噪声和不确定性更鲁棒

❌ 缺点

  • 需要构造大量的关系对
  • 计算复杂度较高（O(n²)）
  • 对高维问题效果可能下降

🔑 关键理解

REMO的核心循环是：用少量真实评估的解训练关系模型 → 用模型在大量候选解中筛选出最有潜力的几个 → 对这几个进行真实评估 → 重复。

这样可以用10次代理模型评估代替1次真实评估，大大节省了计算资源！

🔧 三、各模块详细解析

🎲
模块1：拉丁超立方采样初始化

功能说明

用拉丁超立方采样（Latin Hypercube Sampling, LHS）生成初始种群，确保样本均匀覆盖整个决策空间。

📝 通俗解释

假设你要在一片正方形区域内撒100个点：

  • 随机撒点：可能东一坨西一坨，分布不均匀
  • 拉丁超立方：把区域分成100个小格子，每个格子里撒一个点，保证全覆盖

拉丁超立方采样示意图

代码逻辑

% 确定初始种群大小
if Problem.D <= 10
    N = 11*Problem.D - 1; % 低维：11D-1个
else
    N = 100; % 高维：固定100个
end

% 拉丁超立方采样
PopDec = UniformPoint(N, Problem.D, 'Latin');

% 映射到实际变量范围
Population = Problem.Evaluation(...
    repmat(Problem.upper-Problem.lower, N, 1) .* PopDec + ...
    repmat(Problem.lower, N, 1));

✅ 优点

  • 保证初始种群均匀分布
  • 覆盖整个决策空间
  • 比纯随机采样更高效

❌ 缺点与改进

  • 种群大小固定，可能不适应不同问题
  • 改进：可自适应调整种群大小
  • 改进：可结合问题特性优化采样策略

模块2：参考解选择（RefSelect）

功能说明

从当前种群中选出k个代表性解作为参考解，用于后续的关系对构造。

📝 通俗解释

参考解就像"代表"：

  • 这样通过比较同学们和这6个代表的关系，就能大致了解每个同学的水平

🎯 雷达网格的核心思想

雷达网格把多维目标空间投影到2D平面上，就像把地球投影到地图上一样。然后在2D平面上划分网格，保证选出的参考解在各个网格中都有分布，这样就能覆盖整个Pareto前沿。

关键公式

适应度 = 0.1 × M × 收敛性 - 最小距离

选择适应度最小的解：既收敛好（值小），又远离已选解（距离大）

✅ 优点

  • 兼顾收敛性和多样性
  • 保证极端解被选中
  • 自适应调整网格精度

❌ 缺点与改进

  • 雷达网格投影可能损失信息
  • 高维问题网格划分困难
  • 改进：可引入自适应网格策略
  • 改进：可结合聚类方法

模块3：PBI分类（GetOutput_PBI）

功能说明

基于PBI（Penalty-based Boundary Intersection）方法，将种群中的解分为"好"和"不好"两类。

📝 通俗解释

想象你站在原点（理想点），面前有很多条路（参考方向）：

  • 每条路上都有行人（解）
  • PBI会判断每个行人是否在某条路的"合理范围"内
  • 在范围内的是"好解"，超出范围的是"不好解"

PBI分类示意图

PBI公式

PBI值 = d₁ + δ × d₂

其中：
d₁ = 解在参考方向上的投影距离（沿参考方向）
d₂ = 解偏离参考方向的垂直距离（惩罚项）
δ = 惩罚参数（控制好解区域的宽度）

🔑 自适应惩罚参数

REMO使用二分法自动调整δ值，使得"好解"的比例保持在30%~70%之间。这样可以避免：

  • δ太大：几乎所有解都是"好解"，分类没有意义
  • δ太小：几乎所有解都是"不好解"，训练数据不均衡

✅ 优点

  • 自适应调整分类阈值
  • 保证训练数据均衡
  • 基于分解思想，适合多目标

❌ 缺点与改进

  • 依赖参考解的质量
  • PBI可能丢失边界解
  • 改进：可结合其他分解方法（如Tchebycheff）
  • 改进：可引入模糊分类

模块4：关系对构造（GetRelationPairs）

功能说明

将解两两配对，生成训练关系模型所需的关系对数据。

📝 通俗解释

关系对就像"比较题"：

  • 题目：[解A, 解B]
  • 答案：A比B好(+1) / 一样好(0) / A比B差(-1)
  • 通过大量这样的"比较题"，模型就能学会判断两个解谁更好

四种关系对类型

类型 组合方式 标签 含义
C1-C2 好解 vs 不好解 +1 好解优于不好解
C2-C1 不好解 vs 好解 -1 不好解劣于好解
C1-C1 好解 vs 好解 0 两者质量相当
C2-C2 不好解 vs 不好解 0 两者质量相当

关系对构造示意图

数据平衡策略

为了防止模型偏向某一类，REMO会平衡各类关系对的数量：

  • 以"C1-C2"配对数为基准
  • 如果同类配对太多，随机采样
  • 如果同类配对太少，从另一类补充

✅ 优点

  • 构造简单，易于理解
  • 平衡采样避免类别偏斜
  • 关系标签比绝对值更容易学习

❌ 缺点与改进

  • 组合爆炸：O(n²)复杂度
  • n=100时产生9900个关系对
  • 改进：REMO_DiRel引入上限采样（pairMax=6000）
  • 改进：可引入主动学习策略选择最有价值的关系对

模块6：代理模型辅助选择（RSurrogateAssistedSelection）

功能说明

用训练好的关系模型指导遗传算法，从大量候选解中筛选出最有潜力的解进行真实评估。

📝 通俗解释

想象你是一个HR，要从1000个简历中选10个人面试：

  • 简历筛选（代理模型）：快速浏览简历，选出100个看起来不错的
  • 面试（真实评估）：对这100个进行深入评估，最终选10个
  • 这样比直接面试1000个人高效多了！

评分机制详解

对每个候选解Xi，计算它与已知好解(C1)和不好解(C2)的关系：

  • 与好解的关系：如果Xi比大多数好解都好 → 高分
  • 与不好解的关系：如果Xi比大多数不好解都好 → 高分
  • 最终得分 = 正类得分 - 负类得分

✅ 优点

  • 高效筛选，节省评估次数
  • GA保证解的多样性
  • 模型指导搜索方向

❌ 缺点与改进

  • 阈值3.9是固定的经验值
  • 评分计算量较大
  • 改进：可自适应调整阈值
  • 改进：REMO_DiRel引入仲裁机制

📊 五、优缺点总结

✅ REMO的优点

  • 关系学习：不需要预测绝对值，只需要比较关系
  • 代理模型辅助：用模型筛选，节省真实评估次数
  • 参考解策略：RSEA保证多样性和收敛性
  • 自适应PBI：自动调整分类阈值
  • 易于实现：基于MATLAB神经网络工具箱

❌ REMO的缺点

  • 关系对爆炸：O(n²)复杂度，样本多时计算量大
  • 单网络不稳定：随机初始化导致结果波动
  • 固定阈值：评分阈值3.9是经验值
  • 无难度感知：对所有目标一视同仁
  • 高维挑战：决策变量维度高时效果下降

🚀 六、改进方向（REMO_DiRel的创新）

💡 创新1：难度感知目标子集选择

问题：超多目标问题中，不同目标的建模难度差异很大，难目标会拖累易目标。

解决方案：在线评估每个目标的难度，选出最易建模的目标子集进行训练。

效果：子目标建模更准确，训练更快。

💡 创新2：双尺度集成网络

问题：单个神经网络不稳定，容易过拟合。

解决方案：

  • 训练全目标网络（看全局）
  • 训练子目标网络（看细节）
  • 用Bagging集成多个网络，计算均值和方差

效果：预测更稳定，方差可用于判断置信度。

💡 创新3：逐候选逆方差仲裁

问题：传统方法用固定权重融合两个模型，不够灵活。

解决方案：对每个候选解，哪个模型更确定（方差小），就更信任它。

效果：自适应融合，冲突时有明确的处理策略。

💡 创新4：难度感知GA参数

问题：固定GA参数无法适应不同难度的搜索阶段。

解决方案：易目标时更局部搜索（exploit），难目标时更全局搜索（explore）。

效果：搜索策略自适应调整，效率更高。
