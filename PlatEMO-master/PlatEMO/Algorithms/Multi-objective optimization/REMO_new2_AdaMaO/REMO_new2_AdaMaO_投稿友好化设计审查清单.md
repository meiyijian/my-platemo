# REMO_new2_AdaMaO 投稿友好化设计审查清单

> 用途：逐项标记当前算法中“难以解释、难以归因、需要额外敏感性实验”的设计，并为后续代码改造选择更常规、更容易写入论文的方法。  
> 审查对象：当前完整版 `REMO_new2_AdaMaO.m` 及其直接调用模块。  
> 审查原则：不是单纯追求代码短，而是尽量让每个保留模块都能回答三个问题：为什么需要、解决什么明确失败模式、消融是否支持。

---

## 一、先给结论：建议保留什么，主线改成什么

### 1. 建议保留的核心创新

建议把投稿版的核心收缩为一条主线：

> **面向昂贵多目标优化的可靠性感知关系学习：用全局与局部双视角生成关系监督，并根据监督可靠性连续调节模型训练与候选选择。**

建议保留四个必要环节：

1. **关系学习而非逐目标回归**：网络学习两个决策向量之间的相对关系，输出直接服务候选排序。
2. **全局—局部双视角伪标签**：保留参考向量场与动态参考解两个信息源，但把二者统一成同尺度连续得分。
3. **可靠性感知训练**：保留“信号越一致，关系对越可信”的思想，用连续软权重实现，不再切换三套训练模式。
4. **代理辅助候选筛选**：保留内部 GA 产生候选池、关系模型排序、少量真实评估的 REMO 主流程；批次多样性可采用常规 max-min 选择。

### 2. 不建议再作为核心创新的内容

- PIEA 三指标轮盘、PF 形状估计、指标 SVR、SDR 反馈闭环。
- `conservative/curriculum/weighted` 三种关系训练模式的硬切换。
- `conservative/explore/indicator` 三种候选模式的硬切换。
- 基于 SVD 的 `degeneracy >= 0.45` 模式门控。
- `coverage < 0.60` 模式门控。
- 候选探索公式中多层归一化、分位数筛选、动态系数和加权多样性公式的叠加。

这些内容并非完全没有动机，而是当前代码与实验很难证明“必须这样组合”。如果全部保留，论文容易被审稿人评价为 heuristic stacking、参数堆叠或缺乏因果归因。

## 三、最需要修改的复杂设计

## A1. 候选解探索公式：当前复杂度超过论文收益

代码位置：

- `AdaMaOSelection.m:124`：进入 explore 选择。
- `AdaMaOSelection.m:148-166`：关系得分和不确定性归一化、动态 `lambda_t`、分位数筛选。
- `AdaMaOSelection.m:392-439`：用 `0.75/0.25` 再混合质量与距离。

当前实际流程为：

1. 将关系得分归一化为 `score_n`；
2. 将不确定性归一化为 `unc_n`；
3. 计算

   ```matlab
   lambda_t = lambda0 * (1-ratio) * max(0,1-p_err/0.45);
   score_aug = score_n + lambda_t * unc_n;
   ```

4. 用 `quantile(score_aug,q_keep)` 截取一部分候选；
5. 在截取后的集合中，再用

   ```matlab
   acq = 0.75*score_norm + 0.25*distance_norm;
   ```

   贪心选出 4–6 个解。

### 审稿人可能追问

- 为什么是不确定性加法，而不是乘法、LCB、EI 或 Thompson sampling？
- 为什么误差基准固定为 `0.45`？三分类随机误差或多数类误差与它有什么关系？
- 为什么 `lambda0=0.35`？
- 为什么先取 80% 分位数，再用另一个分数选择？
- 为什么质量与距离是 `0.75:0.25`？
- 六个设计选择中究竟哪一个带来收益？

这会迫使论文至少增加多组敏感性和消融实验，但即使做完，主线仍显得像经验采集函数。

### 推荐的常规版本

推荐采用“单一采集分数 + 标准批多样性”两步法：

```matlab
reliability = max(0, 1 - p_err / p_base);
beta_t      = (1-ratio) * reliability;
acq         = quality_score + beta_t .* uncertainty;

pool = topK(acq, min(5*n_eval,numel(acq)));
Next = maxMinSelect(Candidates(pool,:), n_eval);
```

其中 `p_base` 使用多数类分类器的错误率或交叉验证基线，不再引入固定 `0.45`。论文只需解释：模型相对基线越可靠，早期越允许不确定性探索；随后用常规 max-min 构造分散批次。

更激进、也更容易发表的版本是直接使用：

```matlab
acq = quality_score + (1-ratio).*uncertainty;
```

然后把可靠性只用于训练权重，不在候选层再次使用。

建议标记：

- [ ] 采用“质量 + 时变不确定性 + max-min”
- [ ] 采用纯质量 top-K，先做最简基线
- [ ] 保留当前复合公式，并补完整敏感性实验

## A2. 候选三模式不是有效的动态自适应

代码位置：`REMO_new2_AdaMaO.m:198-202`。

当前规则：

```matlab
if use_indicator && p_err <= 0.35 && degeneracy >= 0.45
    candidate_mode = 'indicator';
elseif p_err <= 0.35 && coverage < 0.60
    candidate_mode = 'explore';
else
    candidate_mode = 'conservative';
end
```

现有 160 次运行、5447 代诊断已经给出直接证据：

- 68% 的运行候选模式从头到尾零切换；
- `coverage < 0.60` 基本恒真，属于死条件；
- `degeneracy` 与目标数强耦合，导致 M=20 大量进入 indicator、M=10 大量进入 explore；
- conservative 候选模式全局仅约 1.3%，接近死代码；
- DTLZ7 M=20 出现双稳态锁定，阈值把不同随机运行锁进不同模式。

因此，论文中若声称“随搜索状态动态切换候选策略”，审稿人只要查看模式轨迹就可能发现它更像“第一代完成问题分类，之后静态执行”。

### 推荐处理

彻底取消 `candidate_mode`，所有候选统一执行一个连续采集函数。状态量只连续改变系数，不触发不同算法分支。

这仍然可以称为 adaptive，但适应发生在采集强度上，而不是三个异构选择器之间跳转。

建议标记：

- [ ] 删除三模式，改为连续权重
- [ ] 只保留 explore 作为统一候选选择
- [ ] 保留模式切换，但必须重设计诊断量并补模式轨迹证据

建议标记：

## A4. Hybrid PBI 应保留思想，但重写数学形式

代码位置：`HybridPBI_Classification.m:60-108`、`GetOutput_PBI.m:52-73`。

### 当前不易解释之处

当前融合的是：

- `score_v = 1/(1+PBI_v)`：连续全局质量分数；
- `label_dyn ∈ {0,1}`：通过动态参考解和自适应阈值得到的二值标签。

然后直接计算：

```matlab
score_hybrid = alpha*score_v + (1-alpha)*label_dyn;
confidence   = 1 - abs(score_v-label_dyn);
```

问题在于两个信号不在同一统计语义上：一个是未经校准的连续 PBI 变换，一个是人为控制类别比例后的二值判断。后期 `alpha` 变小后，二值项会压倒连续项；所谓 confidence 同时受到绝对质量和二值边界影响，不等同于可校准预测置信度。

更复杂的是，`GetOutput_PBI` 会在 `[-20,20]` 内二分搜索 `delta`，强制好类比例进入 `[0.3,0.7]`。这保证了训练可用性，却很难解释为真实质量边界。

### 推荐的常规版本：连续双视角排名融合

```matlab
s_global = rankNormalize(-PBI_global);
s_local  = rankNormalize(-PBI_local);

alpha    = 1-ratio;
s_mix    = alpha*s_global + (1-alpha)*s_local;
reliability = 1 - abs(s_global-s_local);
```

优点：

- 两个信号都在 `[0,1]` 且语义一致；
- 保留早期重全局、后期重局部的核心思想；
- 可靠性清楚表示两个视角的一致程度；
- 删除 `delta` 二分搜索、`[-20,20]`、`[0.3,0.7]` 等隐藏设计；
- 便于做 `global only / local only / fusion` 三组干净消融。

### 标签构造建议

按 `s_mix` 排序：

- top 25% 作为正锚点；
- bottom 25% 作为负锚点；
- 中间 50% 不直接标成坏类，只用于无监督候选或暂不参与强关系监督。

这样仍然保留 top/bottom 的清晰监督，同时避免把中间解系统性误标为坏类。

建议标记：

- [ ] 改为连续双视角排名融合
- [ ] 保留二值局部标签，但先校准到连续概率
- [ ] 保留当前实现并增加阈值与比例敏感性实验

## A5. 关系训练三模式应合并为一套软加权训练

代码位置：`REMO_new2_AdaMaO.m:114-149`。

三种模式分别是：

- conservative：所有关系对等权；
- curriculum：上一代误差大时，丢弃每类低置信度 20% 样本；
- weighted：模型可靠、平均置信度高且覆盖不足时，用置信度加权。

### 为什么难以写论文

三种模式都在解决同一问题：伪标签有噪声。区别只是“不处理、硬删除、软加权”。把它们写成三模式控制器，会引入 `tau_err=0.35`、`mean_conf=0.55`、`coverage=0.60`、`q_keep=0.80`、`w_min=0.30` 等多个参数。

第二轮实验虽然说明误差尖峰确实会触发 curriculum，但这只能证明“误差尖峰存在”，不能证明“必须切换到硬删除 20%”是最佳处理。更常规的做法是让权重在误差上升时自然收缩。

### 推荐版本

始终使用同一训练接口：

```matlab
pair_conf = sqrt(conf_i .* conf_j);
model_gain = max(0,(p_base-p_err_prev)/max(p_base,eps));
pair_weight = 1 + model_gain .* (pair_conf-1);
```

解释：

- 模型尚无可靠证据时，`model_gain≈0`，所有样本近似等权；
- 模型可靠时，权重逐渐接近视角一致性权重；
- 不硬删除数据；
- 没有模式切换，也不需要 `q_keep` 和 `w_min`。

如果希望更简单，可直接固定：

```matlab
pair_weight = 0.5 + 0.5*sqrt(conf_i.*conf_j);
```

建议标记：

- [ ] 始终软加权
- [ ] 根据模型增益连续收缩权重
- [ ] 保留 curriculum 作为独立消融，不进入主算法
- [ ] 保留当前三模式

## A6. 候选关系得分应改为标准净胜率

代码位置：`AdaMaOSelection.m:253-373`。

当前每个候选与好类、坏类各做正反方向比较，再把三个输出类别的概率手工分配到 `C_SCORE(1)` 和 `C_SCORE(2)`，最终取差值。公式较长，并且“同类概率”在与好类比较时会被算作候选好的证据，这种语义很容易被追问。

### 推荐版本 1：期望胜率

令网络输出 `P(X_i ≻ X_j)`，候选分数定义为：

```matlab
score(x) = mean_j P(x ≻ positive_anchor_j) ...
         + mean_k P(x ≻ negative_anchor_k);
```

如果保留三分类，可用：

```matlab
win_prob = P(win) + 0.5*P(tie);
score(x) = mean(win_prob_x_vs_anchor);
```

这相当于常规 pairwise ranking 的期望胜率，公式短、概率语义明确。

### 推荐版本 2：正负锚点 margin

```matlab
score(x) = mean P(x ≻ negative_anchor) ...
         - mean P(positive_anchor ≻ x);
```

它直接表示“战胜负锚点的能力减去被正锚点压制的程度”。

建议标记：

- [ ] 改为期望胜率
- [ ] 改为正负锚点 margin
- [ ] 保留当前四组证据公式

## A7. 关系对生成与测试误差存在泄漏风险

代码位置：`GetRelationPairs.m`、`GetRelationPairs_confidence.m`、`DataProcess.m`、`DataProcess_confidence.m`。

当前先从同一批基础解生成大量笛卡尔积关系对，再随机按关系对划分 75% 训练、25% 测试。这意味着同一个基础解很可能同时出现在训练对和测试对中。测试误差衡量的是“见过这些端点后预测新组合”的能力，而不是对新解的泛化能力。

由于 `p_err` 又用于模式路由和探索系数，这个偏乐观误差会进入控制环。

### 推荐版本

先按基础解划分：

1. 将 Population 按解划分为训练锚点和验证锚点；
2. 训练关系对只由训练锚点生成；
3. 验证关系对至少一端来自验证锚点；
4. 使用交叉验证或固定 holdout 误差作为可靠性估计。

同时避免完整笛卡尔积：每个解只采样固定数量的同组邻居和跨组锚点，使关系对规模从近似 `O(N²)` 降到 `O(NK)`。

该修改不是为了“好写公式”，而是提升论文方法学可信度，优先级很高。

建议标记：

- [ ] 按基础解划分训练/验证
- [ ] 限制每个解的关系对数量
- [ ] 两项都改
- [ ] 暂时保留

## B1. 自适应 K-means 参考向量

代码位置：`HybridPBI_Classification.m:139-216`。

高维时对当前非支配解做 K-means，使用 `MaxIter=100`、`Replicates=5`，中心不足时重复扩充。风险包括：

- 参考方向受当前种群偏差影响，可能产生“当前覆盖哪里，就继续强化哪里”的正反馈；
- 引入额外随机性；
- 需要解释为何低维用均匀向量、高维用 K-means，以及边界为什么是 `M<=3`、`N<50`；
- 若未做独立消融，它不应被包装成必需模块。

建议投稿首版先用统一均匀参考向量。若 K-means 明显改善不规则 PF，再作为独立模块保留，并提供 `UniformOnly` 消融。

## B2. 网络规模随输入维数膨胀

代码位置：`REMO_new2_AdaMaO.m:463-465`。

当前使用：

```matlab
patternnet([ceil(1.5*xDim), xDim, ceil(xDim/2)])
```

其中 `xDim=2D`。该结构没有直接理论依据，且 D 增大时参数量快速增长。建议改为：

## 五、推荐的投稿版算法结构

## 方案 S：最推荐，结构最干净

### 模块 1：连续双视角质量估计

```matlab
s_global = rankNormalize(-PBI_global);
s_local  = rankNormalize(-PBI_local);
s_mix    = (1-ratio)*s_global + ratio*s_local;
conf     = 1-abs(s_global-s_local);
```

### 模块 2：锚点关系监督

- top 25%：正锚点；
- bottom 25%：负锚点；
- 中间解不直接赋为坏类；
- 每个锚点只采样有限数量关系对；
- 关系对权重由两端 `conf` 的几何平均给出。

### 模块 3：单一关系模型

- 使用固定小型 MLP；
- 按基础解划分训练/验证；
- 用验证误差相对多数类基线的增益衡量模型可靠性。

### 模块 4：单一候选采集

```matlab
quality = expected_pairwise_win_rate;
beta    = (1-ratio)*model_reliability;
acq     = quality + beta*uncertainty;
```

- 先按 `acq` 取 top-K 候选池；
- 再用纯 max-min 选出 `n_eval` 个真实评估解。

### 模块 5：环境选择

保留 REMO 原有 `RefSelect`，避免同时改变过多模块；待主算法稳定后再比较常规参考向量选择。

### 论文可写成的三个贡献

1. 提出一种面向昂贵多目标优化的双视角关系监督方法，用全局方向质量与局部参考质量共同构造稳定的关系标签。
2. 提出可靠性感知的关系学习机制，以视角一致性连续调节关系对贡献，缓解动态伪标签噪声。
3. 提出基于关系胜率与模型不确定性的批候选选择方法，在有限真实评估预算下平衡利用、探索与批次多样性。

这三点彼此衔接，且每点都能设计清晰的单模块消融。
