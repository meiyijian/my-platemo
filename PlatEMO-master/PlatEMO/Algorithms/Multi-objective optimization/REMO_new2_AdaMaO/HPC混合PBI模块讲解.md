# HPC 混合 PBI 分类模块讲解（小白版）

> 对应文件：`HybridPBI_Classification.m`（主文件）+ `GetOutput_PBI.m`（动态标签）+ 内部函数 `AdaptiveReferenceVectors`（自适应参考向量）
> HPC = **H**ybrid **P**enalty-based **I**ntersection（混合 PBI）分类

---

## 一、这个模块到底在干嘛？（先建立一个大局观）

多目标优化（比如同时让"成本最低、寿命最长、重量最轻"）里，一个**解**就是一组决策变量（比如设计参数）对应的多个目标值。

算法每一代会有一堆候选解。HPC 模块的任务就一句话：
**给这堆解挨个贴"好 / 坏"标签。**

为什么要贴标签？因为 REMO 系列的核心套路是"关系学习"——它要用**好解 vs 坏解**组成"关系对"去训练一个神经网络（让模型学会"什么叫好解"），之后用模型去挑下一批该真实评估的解。

所以：**HPC 的分类质量，直接决定后面训练数据干不干净。** 它是整条流水线的"质检第一关"。

---

## 二、前置知识：什么叫 PBI？

PBI 来自经典算法 MOEA/D（基于分解的多目标进化算法）。它解决一个核心难题：

> 多目标问题里没有"唯一最优解"，只有一条**帕累托前沿（Pareto Front）**——一堆"互不支配"的解。
> 怎么判断一个解"够不够好"？PBI 给它一个**标量分数**。

把第一张图记在脑子里：

- 每个目标是一根坐标轴，原点是"理想点"（每个目标都取最小值）。
- 我们设一条**参考方向 w**（希望解落在这条射线上）。
- 任意解 P 到理想点，可以拆成两截：
  - **d1**：沿参考方向的长度（解离理想点"前进了多远"）—— 越短越好（更接近理想）。
  - **d2**：偏离参考方向的垂直距离（解"歪"了多远）—— 越短越好（越贴方向）。
- **PBI = d1 + θ · d2**（θ 是惩罚系数，默认 5，越大越容不得"歪"）。

**PBI 越小 = 这个解越好。** 这就是 PBI 的全部直觉。

## 三、HPC 的"混合"：两套信号揉在一起

光用一套 PBI 不够稳，所以 HPC 同时算**两个信号**，再加权融合：

### 信号 A：参考向量场得分 `score_v`（全局视野）
- 先准备一组**参考向量**（方向），低维/小种群用均匀分布的；高维时用 **K-means 聚类非支配解**自适应生成（见内部函数 `AdaptiveReferenceVectors`）—— 让方向贴合当前真实的帕累托前沿形状。
- 每个解找"最对味"的参考向量，算它的 PBI_v = d1 + θ·d2，再转成分数 `score_v = 1/(1+PBI_v)`，落在 **[0,1]** 之间，连续、细腻。
- 优点：看全局，对所有解一视同仁。

### 信号 B：动态参考解标签 `label_dyn`（局部视野）
- 用 RSEA 策略从当前种群挑 **k 个代表性参考解 `Ref`**（默认 k=6）。
- 对每个解，算它相对最近参考解的 PBI（公式见 `GetOutput_PBI.split_data`），**超过阈值就标"坏"(0)，否则"好"(1)**。
- 阈值 `delt` 是自适应的：二分搜索让"好"的比例落在 **30%~70%**，避免类别极端失衡。
- 优点：贴当前种群的局部真实情况。

### 融合：`score_hybrid = α · score_v + (1-α) · label_dyn`
- `α = 1 - ratio`，`ratio` = 已用评估次数 / 总预算。
- **早期**（ratio 小，α 大）：更信全局参考向量场。理由：种群还散、参考解也不稳，全局信号更靠谱。
- **后期**（ratio 大，α 小）：更信局部动态标签。理由：种群已聚集，局部信号更准。

### 置信度：`confidence = 1 - |score_v - label_dyn|`
- 两个信号越一致，置信度越高 → 这个"好/坏"判断越可信。
- 后面关系对生成（加权模式）就用这个置信度当权重。

### 最后输出
按 `score_hybrid` 降序排：
- 前 **N/4** → **好解**（`good_idx`，`Catalog=true`）
- 后 **N/4** → **坏解**（`bad_idx`）
- 同时返回 `confidence`（每解置信度）和 `Ref`（参考解，给后续 RefSelect 用）

## 五、缺陷与坑（重点，讲人话）

这套模块能用，但以下问题是实打实存在的：

1. **中间一半解被"冤枉"成坏解。**
   它只取前 N/4 当"好"、后 N/4 当"坏"，中间那一半（N/4 ~ 3N/4）全被丢进 `Catalog=false` 的"坏类"。明明是中不溜的解，也被当成坏。关系模型只能用最两端训练，**丢了大量中间信息**。

2. **α 只看"进化比例"，不看"真实状态"。**
   `α = 1 - ratio` 纯按时间线性衰减。但早期模型可能已够稳（该早用局部信号），后期种群可能已退化（局部信号也未必好）。切换时机该由"运行时诊断"驱动，而不是单纯按时间——这正是 AdaMaO 后面加 `RuntimeDiagnostics` 想补的，但 HPC 这一层本身没接上。

3. **连续分数被 0/1 硬标签"绑架"。**
   `score_hybrid = α·score_v + (1-α)·label`。`label` 只有 0 或 1，当 `(1-α)` 不小（比如后期）时，这个 0/1 的跳跃会**完全压过 `score_v` 的细腻差**。结果：同一"好"标签内的两个解，谁更好，分数区分不出来。

4. **置信度是"假自信"。**
   `confidence = 1 - |score_v - label_dyn|` 只衡量"两个信号是否一致"，不衡量"分类是否真对"。如果两套信号**一起错**（都往同一方向错），差值照样小 → 置信度照样高。这是典型的"一致≠正确"。

5. **两套"参考"口径不一致。**
   信号 A 用参考向量场 V（均匀/K-means 聚类），信号 B 用参考解 Ref（RSEA 选的 k 个）。两者"方向"来源不同，**融合时可能互相打架**。

6. **两套不同的 PBI 公式在打架。**
   信号 A：`PBI_v = d1 + θ·d2`，θ 固定 5。
   信号 B（`split_data`）：`g = ‖P-Zmin‖·cosθ + delt·‖P-Zmin‖·sinθ`，再除以参考解距离归一化。
   两套公式、两套阈值（θ=5 写死 vs delt 二分搜 [-20,20]），**量纲不统一、语义不完全对等**，融合时其实在拿两个不完全同尺度的东西相加。

7. **θ 固定 = 5，不自适应。**
   高维目标下，d1（收敛）和 d2（偏离）的最佳平衡是变化的，但惩罚系数写死了，无法随问题调整。

8. **delt 二分搜索只为"凑比例"，不为"凑质量"。**
   它强制让 30%~70% 被标"好"，不管真实质量分布。如果某一代本来就几乎全好 / 全坏，硬切一刀反而**往标签里掺噪声**。

9. **效率与可复现性。**
   - 逐解 for 循环算 d1/d2 + `pdist2` + K-means，MATLAB 下大种群/高维会很慢。
   - K-means 随机初始化 → 每次跑出来的参考向量可能不同 → **分类结果不确定**，复现实验要固定随机种子。

10. **数值小补丁。**
    `split_data` 里给 `CosineP` 减了 `1e-6` 来防止 `sqrt(1-cos²)` 出 NaN/复数，属于打补丁式写法，边界处仍可能不稳。

---

## 六、一句话总结

> HPC 混合 PBI 模块 = **"全局参考向量场(连续分) + 局部动态参考解(二分标签)"两套 PBI 信号，按进化进度加权融合，给解贴好/坏标签并给置信度**。
> 它思路清楚、兼顾全局与局部，但"中间解被冤枉、α 太死板、连续分被硬标签绑架、置信度假自信、两套 PBI 公式不一致"这几个坑，是后续改进（运行时诊断、动态模式切换）要重点补的地方。

## 七、常见疑问：自适应参考向量 vs MOEA/D 均匀向量，矛盾吗？

**结论先说：不矛盾，两者是给不同用途、在不同层面上服务的，没有谁"错"。**

### 1. 本模块的自适应参考向量到底怎么运作？
代码位置 `AdaptiveReferenceVectors`（HPC 内部函数），只在 **M>3 且 N≥50** 时启用，否则退回均匀向量：
1. 取当前种群的**第一层非支配解**（真正的帕累托前沿近似）；
2. 把它们的目标值归一化到 [0,1]；
3. 用 **K-means 聚类**得到若干簇中心；
4. 簇中心映射回原空间、再归一化为**单位方向向量** → 这些就是"自适应参考向量"。

直觉：**非支配解的分布形状 = 当前前沿的形状**，所以这些方向天然贴着前沿，哪里解多方向就密。而且因为 HPC 每代都被调用，这些向量是**跟着前沿一起演化**的。

### 2. MOEA/D 的均匀参考向量怎么运作？
MOEA/D 在**初始化时**用 `UniformPoint`（默认 NBI/Das-Dennis 单纯形格点，本模块均匀回退用的是 'ILD' 增量格点）撒一把**均匀分布**的方向，**整轮固定不变**。每个方向 = 一个子问题（子目标），演化中每个子问题固定持有 1 个解。

### 3. 为什么不矛盾？—— 用途根本不同
| | MOEA/D 均匀向量 | REMO HPC 自适应向量 |
|---|---|---|
| 角色 | 是**子问题分解方向**，定义"该优化什么" | 只是**一把尺子**，用来给解算 PBI 打分 |
| 是否每人一题 | 是，每个方向必须恰好对应 1 个解 | 否，只用来衡量，不规定"每方向一个解" |
| 为何要均匀 | 保证整条前沿被**均匀覆盖**，不漏区域 | 不需要均匀覆盖，只要方向**落在有解的地方**才有意义 |
| 是否随演化变 | 基础版固定；自适应变体才更新 | 每代重算，跟踪前沿 |

MOEA/D 必须把向量铺满整段空间，否则某些区域永远没解（"漏覆盖"）；REMO HPC 只拿向量当评分标尺，自然希望向量**指向真正有解的区域**，均匀反而会在空白区产生无意义的 PBI。

### 4. 哪个"正确"？
都正确，看你拿它干什么：
- **均匀向量**优势是空间覆盖稳、对不规则前沿也"至少每个方向都尝试过"；劣势是在**退化/不连续 PF**上，很多均匀方向指向空白 → 对应子问题无解（MOEA/D 经典痛点，浪费评估）。
- **自适应向量**优势是 PBI 只在"有解处"计算，打分更 discriminating；劣势是**正反馈风险**——若种群已挤在一块，自适应向量也跟着挤过去，反而削弱探索压力。所以本模块（a）只把它用于**打分而非驱动搜索**，（b）低维/小种群时**退回均匀**，正是为了兜底这个风险。
- 补充：自适应参考向量并非"反 MOEA/D"，它本就是 MOEA/D 家族的演进分支（MOEA/D-AWA、RVEA、AR-MOEA 等都做权重/参考向量自适应）。
