# 03 · 运行时诊断（模块 3）

> **一句话定位**：运行时诊断是 AdaMaO **唯一完全自创的模块**——它不是任何已有算法的改进，而是 AdaMaO 为"自适应"专门设计的**传感器**。两个数字（coverage + degeneracy）驱动后面两个开关（关系对模式 + 候选解模式），没有它，AdaMaO 就退化为 WFG10 的固定策略。

源码位置：`REMO_new2_AdaMaO.m` 的 `RuntimeDiagnostics` 局部函数（L276–L339），主循环中调用在 L97：`diagnostics = RuntimeDiagnostics(Population,N);`

---

## ① 它解决什么问题？（为什么 WFG10 缺它不行）

回忆模块 0 的核心论断：**WFG10 的策略是写死的，不会看种群状态做调整。**

写死策略在两类情况下会出错：

| 阶段 | 现象 | 固定策略的问题 |
|---|---|---|
| 早期 | 种群散、模型不准 | 固定加权 → 噪声权重放大误差 |
| 后期 | 种群退化、挤在低维子空间 | 固定选择 → 关系得分分不出好坏 |

所以需要一个"传感器"来告诉算法：**现在种群处于什么状态？** 然后由模块 4/7 的两个开关据此做决策。

AdaMaO 设计了两个诊断量：

> - **coverage（覆盖率）**：种群覆盖了多少个"参考方向"？
> - **degeneracy（退化度）**：种群是否挤在某个低维子空间里？

---

## ② coverage：种群"散不散"的度量

### 直觉

想象把目标空间均匀铺 N 条参考方向（射线）。如果种群分布广，每条方向上都能分到至少一个解 → 高覆盖率。如果种群挤在一起，大量方向空着没人管 → 低覆盖率。

### 算法步骤（L302–L318）

```
输入：Population（当前种群），Nref（参考方向数量 = N）
输出：coverage ∈ [0,1]

步骤 1：归一化目标值到 [0,1]
步骤 2：生成 Nref 条均匀参考向量 V
步骤 3：把每个解的目标值转成单位方向向量
步骤 4：对每个解，找余弦相似度最高的参考向量（"它最接近哪个方向"）
步骤 5：coverage = 被至少一个解"认领"的参考向量数 / 总向量数
```

关键代码：

```matlab
% 生成均匀参考向量
V = UniformPoint(Nref,M,'ILD');
V = V ./ max(vecnorm(V,2,2),eps);

% 每个解归一化到单位方向
Direction = PopObj ./ max(vecnorm(PopObj,2,2),eps);

% 余弦相似度 = 1 - 余弦距离
cosine = 1 - pdist2(Direction,V,'cosine');
[~,assigned] = max(cosine,[],2);

% 被认领的方向占比
coverage = numel(unique(assigned)) / size(V,1);
```

### 解读

| coverage 值 | 意味着 | 算法该怎么做 |
|---|---|---|
| 接近 1 | 种群分布广，各方向都有解 | 可以信任现有探索 |
| < 0.60 | 种群集中在少数方向，大片区域空白 | **需要多探索**，触发加权/explore 模式 |

### 与 HPC 混合 PBI 的连接

这里有个关键对比——HPC 也用参考向量（信号 A 的 `score_v`），但**用途完全不同**：

| | HPC 参考向量场 | RuntimeDiagnostics 参考向量 |
|---|---|---|
| 用途 | 给每个解算 PBI 打分 | 看多少方向"有解" |
| 生成方式 | M≤3 均匀；M>3 用 K-means 聚类非支配解（自适应） | 始终均匀（ILD 增量格点） |
| 为什么不同 | 打分要向量落在"有解处"才有区分度 | 覆盖率要均匀网格才能衡量"有没有漏方向" |
| 是否变 | 每代重算 | 每代重算 |
| 输出 | `score_v`（每解一个分） | `coverage`（一个数） |

> 🔑 记忆点：HPC 的向量是**评分尺子**（自适应，贴前沿），诊断的向量是**体检网格**（均匀，查漏）。两者都是参考向量，但一个是"打分工具"、一个是"诊断工具"。

## ③ degeneracy：种群"挤不挤"的度量

### 直觉

把 N 个解的目标值看作 N 个 M 维点。如果它们完全分布在一个 M-1 维超平面上（退化前沿），那 SVD 的前 M-1 个奇异值就解释了 100% 能量。如果它们均匀散布在整个 M 维空间，需要全部 M 个奇异值才能解释 90% 能量。

**退化度 = 1 − (解释 90% 能量所需的最小秩 / M)**。
- 接近 0：分布均匀，不退化。
- 接近 1：高度退化，挤在很低的维度里。

### 算法步骤（L320–L338）

```
输入：归一化后的 PopObj
输出：degeneracy ∈ [0,1]

步骤 1：PopObj 去均值（中心化）
步骤 2：SVD 分解 → s（奇异值向量）
步骤 3：energy = s² → total = Σenergy
步骤 4：找到 rank90 = 使累积能量 ≥ 90% 所需的最小秩
步骤 5：degeneracy = 1 − rank90 / M
```

关键代码：

```matlab
Centered = PopObj - mean(PopObj,1);
s = svd(Centered,'econ');
energy = s.^2;
total = sum(energy);
rank90 = find(cumsum(energy)./total >= 0.90, 1, 'first');
degeneracy = max(0, min(1, 1 - rank90/max(M,1)));
```

### 解读

| degeneracy 值 | 意味着 | 算法该怎么做 |
|---|---|---|
| 接近 0 | 种群完全铺满 M 维空间 | 不需要指标增强 |
| < 0.45 | 轻微退化，还在可控范围 | conservative/explore 够了 |
| ≥ 0.45 | 严重退化，解挤在低维子空间 | **触发 indicator 模式**，用指标重排增强多样性 |

**为什么阈值是 0.45？**
- 对于一个 10 目标问题，若 deg = 0.45，意味着 rank90 ≈ 5.5，即只用约 5~6 维就能解释 90% 的分布能量。
- 这说明种群在 10 维目标空间中只占了一半不到的有效维度，是强退化信号。
- 此阈值来自初步经验调参，非严格推导。

### 与 HPC 混合 PBI 的连接

退化度的"高维诊断"角色和 HPC 有天然关联：

- HPC 在高维（M>3）时用 K-means 聚类非支配解生成自适应参考向量——这本身就是对"前沿形状"的响应。
- 如果 `degeneracy` 高，说明非支配解分布窄，K-means 的聚类中心也会跟着挤 → 正反馈恶化。
- 但退化度**不直接修改 HPC 的行为**（这是个缺陷——HPC 的 α 只看 `ratio`，不看 `degeneracy`）。退化度的消费者是**模块 7 的候选解模式开关**。

## ④ diagnostics 如何驱动两个开关？（数据流全貌）

把模块 1~3 串起来看完整的数据流：

```
Population（模块 1 的当前工作集）
      │
      ├─→ [模块 2] HybridPBI_Classification
      │       │
      │       ├─→ Catalog（好/坏标签）──→ 模块 4 生成关系对
      │       ├─→ confidence（置信度）──→ mean_conf + 模块 4 加权
      │       └─→ Ref（参考解）────────→ 模块 8 AdaMaOSelection
      │
      └─→ [模块 3] RuntimeDiagnostics
              │
              ├─→ coverage ──┬──→ 模块 4 关系对模式开关
              │              └──→ 模块 7 候选解模式开关
              └─→ degeneracy ──→ 模块 7 候选解模式开关
```

**两个开关的具体决策逻辑**（主循环 L114–L119、L198–L203）：

### 开关 A：关系对训练模式

```matlab
if prev_p_err > tau_err                       % 上代模型太烂
    → 'curriculum'    （课程学习，只留高置信度样本）
elseif p_err <= tau_err && mean_conf >= 0.55 && coverage < 0.60
    → 'weighted'      （模型准 + 可信度高 + 覆盖低 → 加权鼓励探索）
else
    → 'conservative'  （默认，稳）
```

### 开关 B：候选解选择模式

```matlab
if indicator_model 存在 && p_err <= tau_err && degeneracy >= 0.45
    → 'indicator'     （退化严重 → 指标轮盘重排增强多样性）
elseif p_err <= tau_err && coverage < 0.60
    → 'explore'       （模型准 + 覆盖低 → 鼓励探索）
else
    → 'conservative'  （默认，稳）
```

> 🔑 两个诊断量实际上配合得很有层次——**coverage 管"够不够广"，degeneracy 管"有没有塌缩"**。低覆盖触发 explore（主动去空白区），高退化触发 indicator（被动用指标纠偏）。

## ⑤ 与 REMO / PIEA / HPC 的连接

| 成分 | 来自 | 在 AdaMaO 里的角色 |
|---|---|---|
| 参考向量均匀生成 `UniformPoint(...,'ILD')` | MOEA/D 通用 | 计算覆盖率用的"体检网格" |
| SVD 退化度分析 | 自创（通用线性代数工具，但用于 MOEA 种群诊断是 AdaMaO 首创） | degeneracy 的计算方法 |
| coverage 覆盖率概念 | **AdaMaO 自创** | 与 HPC 的参考向量概念同源但用途正交 |
| **整个诊断模块的存在** | **AdaMaO 自创** | REMO 和 PIEA 都没有任何运行时种群诊断 |
| `mean_conf` | HPC（模块 2） | 配合 coverage 用于加权模式触发条件 |

## ⑦ 进阶讨论：为什么这个模块是关键贡献点？

回顾模块 0 的"借来的 vs 自创的"表格——这是 AdaMaO **最能立住的原创贡献**：

1. **以前没人做过**：REMO 家族前作（REMO、WFG10）都没有运行时种群诊断，PIEA 也没有。这是全新引入的概念。
2. **设计简洁**：只用两个量（coverage + degeneracy），基于通用工具（均匀向量 + SVD），不需要额外真实评估，不引入新超参。
3. **驱动了整套自适应体系**：没有它，关系对模式永远停在 conservative，候选解模式永远停在 conservative，AdaMaO 退化为固定的 REMO 风格。
4. **便于推广**：覆盖面 + 退化度的诊断框架可以移植到其他 SAEA（代理辅助进化算法）上，不绑定 REMO 家族。

> 💡 **答辩技巧**：被问到"和 WFG10 的核心区别是什么"，从 RuntimeDiagnostics 切入——"WFG10 的加权是写死的，AdaMaO 先诊断再决定要不要加权。诊断量 coverage 和 degeneracy 分别对应'覆盖是否不足'和'分布是否退化'，各自驱动不同策略。"
