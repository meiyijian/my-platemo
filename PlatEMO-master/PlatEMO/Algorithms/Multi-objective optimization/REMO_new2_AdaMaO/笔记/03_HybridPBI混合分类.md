# 03 · HybridPBI 混合分类（模块 2）

> **一句话定位**：HybridPBI = 两套 PBI 信号（全局参考向量场的连续分 + 局部动态参考解的硬标签），按进化进度 α 融合，给每个解贴"好/坏"标签并附带置信度。它是整条流水线的"质检第一关"——标签一旦掺噪声，后面的关系对训练、候选筛选全跟着跑偏。

源码位置：
- `HybridPBI_Classification.m` — 主文件（七步走）
- `GetOutput_PBI.m` — 自适应阈值二分搜索（信号 B）
- `RefSelect.m` — RSEA 雷达网格选参考解（信号 A + 信号 B 都用）

主循环中调用在 `REMO_new2_AdaMaO.m` L90：`[~,~,Catalog,confidence,Ref] = HybridPBI_Classification(Population,ratio,...);`

## ① 前置知识：什么叫 PBI？（已在之前的笔记详讲，这里只快速过）

PBI（Penalty-based Boundary Intersection）来自 MOEA/D（Zhang & Li, 2007）：

- 一个解 P 到理想点 Zmin，沿参考方向 w 分解为两段：
  - **d1（收敛距离）**：沿 w 投影长度 → 越短越接近理想点
  - **d2（偏离距离）**：垂直偏离 w 的距离 → 越短越贴合参考方向
- **PBI = d1 + θ·d2**，θ 是惩罚系数（对偏离的容忍度），越小越松、越大越严

高维支配关系失效（M=10 时几乎全非支配），必须用标量化工具把"好不好"压成一个数。PBI 就是这个标量化工具。

**但单靠一套 PBI 不够**：只用全局参考向量场 → 忽略局部前沿形状；只用局部参考解 → 种群散乱时不稳定。所以 HPC 同时算两套信号再融合——这就是"混合"的来源。

## ② 自适应参考向量场（重点讲解）

这是 HPC 里最精巧也最容易被快速略过的部分。不把它讲透，后面两套信号的融合、优缺点都理解不深。

### 2.1 为什么需要"自适应"？

标准 MOEA/D 做法：用 Das-Dennis 单纯形格点在 (M-1) 维超平面上生成**均匀分布**的参考向量，整轮优化不变。

高维下的致命问题：M=10 时，超平面上一半以上的均匀向量指向的空间区域**根本没有 Pareto 前沿**——这些空白区域没有解能"贴到"这些方向上。在空白方向算 PBI = 白白浪费，且这些方向的 PBI 分数大量集中在很差的数值区域，淹没了有解处的区分度。

**解决方案**：不让向量均匀撒满整个空间，而是让向量**贴着当前前沿的实际形状走**。前沿在哪里，向量就指向哪里。

### 2.2 实现：K-means 聚类非支配解 → 参考向量

代码在 `HybridPBI_Classification.m` 内部的 `AdaptiveReferenceVectors` 函数（L139–L216），完整流程：

```
输入: PopObj (N×M), Nref (所需向量数)
输出: V (Nref×M, 单位向量)

┌─ 第 1 步：非支配排序 ──────────────────────────────┐
│   FrontNo = NDSort(PopObj, 1)
│   ParetoObj = PopObj(FrontNo==1, :)    ← 取第一前沿  │
│   若前沿解太少 (< max(10, Nref/2)) → 退回均匀向量    │
└──────────────────────────────────────────────────────┘
        ↓
┌─ 第 2 步：归一化到 [0,1]^M ────────────────────────┐
│   Zmin = min(ParetoObj), Zmax = max(ParetoObj)       │
│   ParetoObj_norm = (ParetoObj - Zmin) / (Zmax-Zmin)  │
│   若某维度无变化 (range < 1e-12) → 退回均匀向量      │
└──────────────────────────────────────────────────────┘
        ↓
┌─ 第 3 步：K-means 聚类 ────────────────────────────┐
│   nClusters = min(Nref, size(ParetoObj,1))           │
│   kmeans(ParetoObj_norm, nClusters,                  │
│          'MaxIter',100, 'Replicates',5,               │
│          'EmptyAction','singleton')                   │
│      → C (簇中心坐标, nClusters×M)                    │
│   若聚类失败 → 退回均匀向量                          │
└──────────────────────────────────────────────────────┘
        ↓
┌─ 第 4 步：簇中心 → 方向向量 ───────────────────────┐
│   V = C .* (Zmax-Zmin) + Zmin     ← 映射回原始空间   │
│   V = V ./ vecnorm(V,2,2)        ← 单位化             │
│   若簇数 < Nref → 重复扩充至 Nref                     │
└──────────────────────────────────────────────────────┘
```

### 2.3 为什么用 K-means 而不是其他聚类？

| 方案 | 为什么不用 |
|---|---|
| DBSCAN（密度聚类） | 前沿解密度不均匀——密集区可能一个簇、稀疏区被当噪声丢弃 |
| 层次聚类 | 需要 N² 距离矩阵，高维种群 N=100 还行，但 N 大时不可行 |
| 高斯混合模型 | 过拟合前沿形状，而且需要设成分数（超参） |
| **K-means** | **简单、直接、每代聚类差异小（Replicates=5 取最优），簇中心天然落在解密集处** |

K-means 的局限：随机初始化 → 不同 run 结果不同（不可复现）。补救：`Replicates=5` 取最好的一次，但仍非确定。投论文时建议固定随机种子。

### 2.4 什么条件下退回到均匀向量？（三重兜底）

```matlab
条件 1: M ≤ 3 或 N < 50           → 直接用均匀（低维/小种群不需要自适应）
条件 2: 非支配解数 < max(10,Nref/2) → 退回均匀（前沿太稀疏，聚类无意义）
条件 3: 某目标维度无明显变化       → 退回均匀（退化前沿，归一化除零）
条件 4: NDSort/kmeans 异常         → 退回均匀（防御性兜底）
```

> 🔑 **记忆点**：自适应向量只在"高维 + 大种群 + 前沿够密集"时启用。一旦条件不满足就退回安全但保守的均匀方案。这种**条件门控 + 多层兜底**的设计是靠谱工程实践。

## ③ 两套 PBI 信号：公式对比（核心）

信号 A（全局连续分）和信号 B（局部硬标签）**用同一个 PBI 数学骨架，但做成了完全不同的"口味"**。理解这一点是读懂 HPC 的关键。

### 3.1 信号 A：全局参考向量场得分 `score_v`（HybridPBI_Classification L60–L82）

**目标**：给出一个细腻的连续分数 ∈ [0,1]，让算法知道"这个解在全局坐标系里大概排第几"。

```
输入: PopObj (N×M), V (Nref×M 参考向量), Zmin (理想点)

对每个解 i (i=1..N):
  ┌─ 找最近参考向量 ──────────────────────────────────┐
  │ vi = argmax_j cosine(P_i, V_j)                      │
  │ w = V(vi,:)                                         │
  └─────────────────────────────────────────────────────┘
  ┌─ 计算 PBI ─────────────────────────────────────────┐
  │ d1 = (P_i - Zmin) · w                              │
  │ proj = Zmin + d1 * w                               │
  │ d2 = ||P_i - proj||                                 │
  │ PBI_v = d1 + θ·d2        (θ = 5, 固定写死)         │
  │ score_v = 1 / (1 + PBI_v)   ∈ [0,1], 越大越好      │
  └─────────────────────────────────────────────────────┘
```

关键特征：
- θ=5 **写死**，不随问题或阶段变化
- 连续分数，能区分"好"和"更好"
- 全部解一视同仁，不依赖任何参考解

### 3.2 信号 B：局部动态参考解标签 `label_dyn`（GetOutput_PBI.m + split_data L79–L135）

**目标**：给出一个二分标签 {0,1}，以当前种群的代表性参考解为标杆，判断"这个解离标杆远不远"。

```
输入: Pop (N×M), Ref (k×M 参考解), Zmin (理想点)

对每个参考解 j (j=1..k):
  ┌─ 找到归属该参考解的子区域中的解 ──────────────────┐
  │ sub_pop = {P_i : argmax_j cosine(P_i, Ref) == j}    │
  └─────────────────────────────────────────────────────┘
  ┌─ 计算 PBI ─────────────────────────────────────────┐
  │ W = (Ref_j - Zmin) / ||Ref_j - Zmin||     ← 方向     │
  │ normP = ||P - Zmin||                       ← 到理想点 │
  │ normR = ||Ref_j - Zmin||                   ← 参考距离 │
  │                                                     │
  │ cosθ = (P-Zmin)·W / (normP * ||W||)                 │
  │                                                     │
  │ g = normP·cosθ + delt·normP·√(1-cos²θ)              │
  │   = normP·cosθ + delt·normP·sinθ                    │
  │   = d1        + delt·d2                             │
  │                                                     │
  │ g = g / normR     ← 用参考解距离归一化              │
  │                                                     │
  │ 若 g > 1 → label = 0 (坏, 比参考解"偏"了)           │
  │ 若 g ≤ 1 → label = 1 (好, 在参考解"附近")           │
  └─────────────────────────────────────────────────────┘
```

关键特征：
- `delt` **自适应二分搜索**（见下一节），不是固定值
- 输出是 **{0,1} 硬标签**，无法区分"好"里的细腻差
- 以参考解为"坐标原点"做归一化 → 判断的是**相对参考解的偏离程度**
- 对所有参考解取并集（任意一个参考解的区域内被判为"好"就算好）

### 3.3 两张公式放一起对比

| | 信号 A：全局 连续分 | 信号 B：局部 硬标签 |
|---|---|---|
| **公式** | `d1 + 5·d2` | `(d1 + delt·d2) / ||Ref-Zmin||` |
| **惩罚系数** | θ=5 **写死** | delt **二分搜索**，自适应凑比例 |
| **归一化** | 无（原始 PBI 距离） | 除以 `||Ref-Zmin||`（相对参考解距离） |
| **参考系** | 均匀/自适应参考**向量场** V | RSEA 选的 k 个动态参考**解** Ref |
| **输出** | 连续分数 [0,1]，能区分"好 vs 更好" | 硬标签 {0,1}，"离标杆远不远" |
| **区分度** | 高（连续值） | 低（同一标签内无区分度） |

> 🔑 **两者从同一数学骨架出发**：信号 A = PBI(unscaled, θ=5)；信号 B = PBI(除以参考距离, delt 自适应)。语义上是**同一个 PBI 家族的两个变体**，不是两套无关的东西在凑。

## ④ 自适应阈值 delt 的二分搜索（信号 B 的核心机制）

信号 B 的阈值 `delt` 不是人为设定的，而是根据当前种群的 PBI 分布**自动二分搜索**出来。代码在 `GetOutput_PBI.m` L52–L71：

```matlab
delt_l = -20;    % 搜索下界
delt_u = 20;     % 搜索上界

while r > 0.7 || r < 0.3      % 目标区间 [0.3, 0.7]
    delt_c = (delt_l + delt_u) / 2;    // 取中点
    用 delt_c 跑 split_data → r = 好解比例

    if r > 0.7    → delt_l = delt_c    // 好太多，delt 变大（更严格）
    if r < 0.3    → delt_u = delt_c    // 好太少，delt 变小（更宽松）
    
    if |delt_l - delt_u| < 0.1 → break  // 区间足够小，停止
end
```

**直觉**：delt 是"惩罚有多重"的旋钮。delt 大 → g 大 → g>1 的解多 → 坏解多（好比例低）；delt 小 → g 小 → g>1 的解少 → 好解多。二分搜索就是让这个旋钮自动拧到**刚好让 30%~70% 的解被判为"好"** 的位置。

**为什么是 30%~70%？** 防止极端类别失衡——若某一代几乎全好/全坏，神经网络的关系对训练数据就全是一个方向的，学不到区分好坏的能力。强制平衡即"标量化打分可能不准，但至少让好坏人各半，避免标签塌缩"。

**局限**：强制平衡不考虑"真实好/坏分布"。如果实际种群已经普遍很好，硬切会往标签里掺噪声——把好解误标的后果比漏标坏解更严重（因为好解被当坏解用，关系对的方向会反过来）。

## ⑤ 融合：α = 1 − ratio 时变权重

```matlab
alpha = 1 - ratio;    // ratio = FE/maxFE ∈ [0,1]
score_hybrid = alpha * score_v + (1-alpha) * double(label_dyn);
```

| ratio | α | 含义 |
|---|---|---|
| 0（开始） | 1.0 | 100% 听全局（`score_v`），0% 听局部 |
| 0.5（一半） | 0.5 | 各占一半 |
| 1（结束） | 0.0 | 0% 听全局，100% 听局部（`label_dyn`） |

**设计直觉**：
- **早期**（ratio 小）：种群散、参考解不可靠 → 信全局参考向量场（均匀覆盖空间，不依赖具体参考解）
- **后期**（ratio 大）：种群聚、全局区分度下降（很多方向变成空白）→ 信局部动态标签（以当前代表性的参考解为准）

**⚠️ 已知缺陷**：α 只看进化比例不看真实种群状态。如果早期模型已经很准（应该早信局部）、后期种群突然退化（局部信号也未必好），α 不会感知。这是模块 3（RuntimeDiagnostics）想补的洞，但目前 HPC 这一层没接上诊断量——解决方向见文末缺陷分析。

## ⑥ 置信度：信号 A 和 B 的"一致程度"

```matlab
confidence = 1 - abs(score_v - double(label_dyn));   // ∈ [0,1]
```

**直觉**：两个信号在同一个解上"同不同意"？同意（差值小）→ 高置信度，不同（差值大）→ 低置信度。

**下游消费路径**：
```
confidence ──→ 模块 2（HPC）                 输出给主循环
              └─→ mean_conf                  加权模式触发条件
              └─→ GetRelationPairs_curriculum 课程学习：保留前 80% 高置信样本
              └─→ GetRelationPairs_confidence  加权训练：confidence → 样本权重
```

**⚠️ 置信度假自信问题**：`confidence` 度量的是"两个信号是否一致"，不是"分类是否正确"。如果两套 PBI 在一个解上**同时判错**（比如都把它高估了），|score_v - label_dyn| 照样小 → 置信度照样高。改进方向：需要外部验证（真实评估后的支配关系）来校准置信度。

## ⑦ 最终输出：好/坏标签 Catalog

```matlab
[~, idx_sorted] = sort(score_hybrid, 'descend');   // 按融合分降序
good_num = ceil(N/4);   bad_num = good_num;
good_idx = idx_sorted(1:good_num);                  // 前 25%
bad_idx  = idx_sorted(end-bad_num+1:end);            // 后 25%
Catalog = false(N,1);   Catalog(good_idx) = true;    // 中间 50% 也标 false
```

**⚠️ "中间解被冤枉"问题**：前 25% 好、后 25% 坏，中间 50% 既不前 25% 也不是后 25%，全被丢进 `Catalog=false`（坏类）。这些解明明是"中不溜"，却被关系对生成当成坏解来配对 → 关系对标签里有系统性偏差。这是整个 REMO 家族（不是 AdaMaO 独有）的结构性问题，源于 `N/4` 硬切。

## ⑨ 已知缺陷与改进方向（按严重程度排列）

| # | 缺陷 | 影响 | 改进方向 |
|---|---|---|---|
| 1 | **两套 PBI 量化不完全对等**（信号 A：d1+5d2 未归一化；信号 B：除以 normR 归一化后再取阈值） | 量纲不统一，融合时权重不完全对等 | 统一除以各自参考系的特征距离 |
| 2 | **α 只看 ratio 不看状态** | 早期该信局部时还在信全局，后期退化时局部信号也不准 | 引入 RuntimeDiagnostics 的 coverage/degeneracy 驱动 α |
| 3 | **N/4 硬切浪费中间信息** | 50% 的解被无辜标"坏"，关系对方向偏 | 用多级标签（好/中/坏）而非二分，或直接用连续分 |
| 4 | **置信度假自信** | 高置信 ≠ 高正确率，加权训练可能放大系统偏差 | 用真实评估后的支配关系校准置信度 |
| 5 | **θ=5 写死** | 不同 M 下 d1 和 d2 的最佳平衡不同 | θ = f(M)，或随退化度自适应 |
| 6 | **信号 B 硬标签压平信号 A** | 后期 (1-α) 大时，0/1 的跳跃压过 score_v 的细腻差 | 信号 B 改为连续分而非 0/1 |
| 7 | **K-means 不可复现** | 不同 run 聚类结果不同 → 分类结果不确定 | 固定随机种子（简单），或换成确定性聚类 |
| 8 | **逐解 for 循环 + pdist2** | MATLAB 下大种群 O(N·Nref·M) 可能慢 | 向量化 d1/d2 计算（MATLAB 矩阵运算替代 for 循环） |

```
                        │ Catalog, confidence    │ coverage, degeneracy
                        ↓                       ↓
                   模块 4 (动态关系对模式) ←── mean_conf + prev_p_err
                        │
                        │ XXs, YYs, WWs
                        ↓
                   模块 5 (关系模型训练)
```

- **上游**（模块 1）：每代的 `Population` 是输入
- **同级**（模块 3）：RuntimeDiagnostics 独立计算 coverage/degeneracy，不和 HPC 耦合——但 `mean_conf` 作为 HPC 的副产品被消费
- **下游**（模块 4）：Catalog → 关系对；confidence → 加权/课程学习筛选
- **模块 8**：Ref（动态参考解）作为 `AdaMaOSelection` 的输入之一
