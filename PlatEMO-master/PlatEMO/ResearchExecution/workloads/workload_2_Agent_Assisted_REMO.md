# Workload 2: Agent-Assisted REMO

## Goal

Build an Agent-assisted expensive many-objective optimization framework. The LLM or Agent layer must not generate raw decision variables. It only chooses from a fixed strategy pool and writes interpretable strategy logs.

## Strategy Pool

- `exploration`: prefer diverse candidates and uncertain regions.
- `uncertainty`: emphasize surrogate uncertainty.
- `difficulty_compensation`: emphasize objectives with slow progress or high error.
- `diversity`: emphasize reference-vector coverage.
- `convergence`: emphasize candidates predicted to dominate or improve PBI.

## State Features

- recent IGD slope;
- recent HV slope;
- surrogate validation error;
- objective-wise improvement rate;
- reference-vector occupancy;
- candidate diversity;
- remaining expensive evaluation budget.

## Controllers

| Controller | Description |
|---|---|
| no-agent | original REMO or Workload 1 method |
| random | randomly select a strategy from the pool |
| rule | deterministic rules based on slopes and errors |
| llm | constrained JSON strategy selector, with rule fallback |

## Safety Contract

The LLM controller must output only:

```json
{
  "strategy": "exploration|uncertainty|difficulty_compensation|diversity|convergence",
  "reason": "short explanation",
  "confidence": 0.0
}
```

If parsing fails or strategy is outside the pool, use the rule controller.

## Deliverables

- Strategy controller design.
- Strategy log per generation.
- Comparison among no-agent, random, rule, and llm controllers.
- Markdown report generated by `D:\MyCode\research-agent-suite`.
- Framework method draft and diagram.

## Acceptance Criteria

The workload is usable for graduation if:

- strategy selection is reproducible and logged;
- LLM choices are constrained and safe;
- at least a prototype experiment shows measurable behavior differences;
- the method can be explained as an optimization framework, not just an API wrapper.
