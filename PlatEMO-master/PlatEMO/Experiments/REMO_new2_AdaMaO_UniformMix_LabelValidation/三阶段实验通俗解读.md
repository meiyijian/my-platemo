# REMO_new2_AdaMaO_UniformMix 前三阶段实验通俗解读

> 写给 MATLAB 基础薄弱的研究生：这个实验到底在做什么？

---

## 🎯 整体研究目标

你的算法叫 **REMO_new2_AdaMaO_UniformMix**，它在解决**昂贵多目标优化**问题。核心思路是：
- 用**代理模型**（替身模型）预测哪些解更好，避免每次都真实评价（太贵）
- 用**关系学习**判断"解 A 是否比解 B 好"
- 但判断好坏需要**标签**（打分），这就是前三阶段要验证的东西

---

## 📋 三个阶段的核心问题

### **阶段1：机制快照审计** —— "算法到底做了什么？"

**研究问题：**
你的算法声称用了一个"混合标签"机制，把两种打分方式结合起来：
1. **锚点标签**（AnchorLabel）：基于"代表解"的二值判断（好/坏）
2. **方向得分**（ScoreV）：基于"非支配解方向"的连续得分

但真的用上了吗？还是只是其中一种在起作用？

**做法：**
- 记录算法每一代的完整快照（种群、方向、得分、标签）
- 检查方向 `V` 到底有多少次真的来自"非支配解的K-means聚类"
- 看看两种得分（`ScoreV` 和 `LabelDyn`）是不是真的不一样
- 验证权重 `alpha=1-FE/maxFE` 是否真的让算法"早期偏方向、后期偏锚点"

**关键专有名词解释：**
- **非支配解（Non-dominated solutions）**：没有被任何其他解"完全压制"的解（在某些目标上更好）
- **K-means**：一种聚类算法，把相似的解分成 k 组
- **PBI（Penalty Boundary Intersection）**：一种距离度量方式
- **代表解（Representative solutions）**：从解集中挑出来代表不同区域的典型解
- **FE（Function Evaluations）**：真实评价次数（你的预算）

**输出：**
- 100个运行任务的快照文件（`.mat`）
- 每个快照记录：种群、方向来源、得分、标签、回退原因
- 统计报告：有多少比例使用了非支配方向 vs 均匀方向

---

### **阶段2：标签因果消融** —— "哪个因素真正起作用？"

**研究问题：**
你的算法同时改了很多东西：
1. 用了更多方向（100个 vs 少量代表解）
2. 用了连续得分（0-1之间）而不是二值（0或1）
3. 固定了正例比例（25%）
4. 动态调整两种得分的权重

到底是哪个因素带来了改进？还是只是碰巧？

**做法：**
设计 **9 种标签版本**（L0-L8），每次只改一个因素：

| 标签版本 | 特点 | 目的 |
|---------|------|------|
| **L0** | 原始二值标签（自然比例30-70%） | 历史基线 |
| **L1** | 锚点连续得分，固定25% | 控制"连续化+固定比例" |
| **L2** | 方向得分，固定25% | 单独测试方向分支 |
| **L3** | 当前完整混合（你的算法） | 待验证版本 |
| **L4** | 固定权重0.5+0.5混合 | 测试"动态权重"是否必要 |
| **L5** | 反向权重混合 | 测试权重方向 |
| **L6** | **打乱对照**：随机打乱ScoreV | 排除"碰巧改善" |
| **L7** | 均匀方向得分 | 测试"非支配方向"是否真比均匀方向好 |
| **L8** | 少量方向（15或30个） | 测试"方向数量"效应 |

**关键操作：**
- 在**同一个种群快照**上重新计算所有标签版本
- 比较它们选出的解有多大重合（Jaccard相似度）
- 看看 L3 是否真的和 L1、L2 都不同（证明融合有意义）
- L6 是关键：如果 L3 和随机打乱差不多，说明改进是假的

**输出：**
- 每个快照的9种标签版本结果
- 重合度矩阵（哪些标签选了相似的解）
- 分歧分析（L3 独有选中的解 vs L1独有、L2独有）

---

### **阶段3：独立真实效用验证** —— "标签真的选对了吗？"

**研究问题：**
前两阶段只是看标签"内部一致性"，但没有用**真实的好坏标准**。阶段3要问：
- 这些标签选出的解，真的离真实 Pareto 前沿（最优解集）更近吗？
- 哪种标签选的解，在后续进化中存活率更高？

**做法：**
用三种"真实效用"来评价每种标签：

#### **效用1：贪心IGD+** ⭐ 最重要
- 从100个解中贪心地选25个，使得到真实PF的距离最小
- 这是"客观最优选择"（Oracle）
- 比较各标签选的25个 vs Oracle选的25个，重合度越高越好

**IGD+（Inverted Generational Distance Plus）**：衡量近似解集到真实PF的平均距离

#### **效用2：留一边际贡献**
- 删掉某个解后，种群的IGD+变差多少？
- 变差越多，说明这个解越重要
- 看各标签是否选中了高贡献的解

#### **效用3：未来生存**
- 被标签选中的解，在后续几代中还留在种群里吗？
- 如果好标签选的解后来都被淘汰了，说明标签可能有问题

**四个预注册假设：**
1. **H1**：非支配方向（L2）比锚点（L1）好
2. **H2**：混合标签（L3）比单独任一分支都好
3. **H3**：动态权重（L3）比固定权重（L4）和反向（L5）好，且早期更依赖方向
4. **H4**：非支配方向（L2）比均匀方向（L7）好

**输出：**
- 各标签的精确度、召回率、NDCG（排序质量）
- 配对统计检验（L3 vs L1, L3 vs L2, ...）
- 决策代码：通过/简化/停止

## 🔬 实验设计的严谨之处

### 1. **配对种子控制**
所有版本在同一个随机种子下运行，保证可比性：
```matlab
seed = problemIndex*10000 + M*100 + run
```

### 2. **三级验证体系**
- **smoke**（冒烟测试）：快速验证代码能跑通（M=3, 1次运行）
- **pilot**（试点）：验证高维场景（M=10, 2次运行）
- **screening**（正式实验）：100个任务（5问题×2维度×10、20目标×5次重复）

### 3. **右删失处理**
如果某些运行没有完成到最后，标记为缺失（NaN），而不是当作"失败=0"

### 4. **多重比较校正**
用 Holm 方法校正 p 值，避免假阳性

### 5. **打乱负对照（L6）**
运行100次随机打乱，看L3是否真的比随机好

## ⚠️ 常见误区提醒

1. **不要把"标签一致性"当"标签正确性"**
   - L3 和 L2 不同 ≠ L3 更好
   - 必须用真实PF验证

2. **不要跨问题直接平均原始得分**
   - 不同问题的 PBI 值尺度不同
   - 只能平均无量纲指标（Jaccard、相关系数等）

3. **不要把 snapshot 当独立样本**
   - 统计单位是 run（独立随机种子）
   - 同一 run 的100个快照是相关的

4. **不要忽略负结果**
   - 如果 L3 不比 L1/L2 好，应该简化算法
   - 如果动态权重无效，应该用固定权重
