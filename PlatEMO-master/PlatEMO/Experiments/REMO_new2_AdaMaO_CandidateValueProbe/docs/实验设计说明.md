# 候选解模块价值探针：实验设计说明

本文档记录**为什么这样设计**，以及每个设计选择对应源码里的哪一行。操作步骤见 [README.md](../README.md)。

---

## 1. 要证明什么

最终 IGD 只能回答"候选模块是否有用"，不能回答"为什么有用"。审稿人会问：是模糊度起作用？是分散起作用？是 SDE 起作用？还是一次评价 4~6 个解起作用？

因果链需要中间环节：

```
候选选择策略 → 候选质量 → FE 效率 → 最终 IGD
                  ↑
             这一环需要单独测量
```

本探针测量中间那一环，用两个指标：CSR（选出的候选能否进入后续种群）和 Oracle overlap（在同一池内是否选到了真正高价值的批次）。

---

## 2. 最关键的设计决策：V1 的存在

### 2.1 真正的混杂因素不是 batch size

一个常见误判是"REMO 每代评价 1 个，Full 评价 4~6 个"。核对源码后这个前提是错的。

原版 REMO 的内循环（[RSurrogateAssistedSelection.m:27-47](../../../Algorithms/Multi-objective%20optimization/REMO/RSurrogateAssistedSelection.m#L27-L47)）：

```matlab
while i < wmax
    [soerted_index,~] = model_select(Smodel,Next);
    Input = Next(soerted_index(1:length(Ref)),:);
    Next  = OperatorGA(Problem,[Input;Ref.decs],{1,15,1,5});   % Next 被整体覆盖
    i     = i + size(Next,1);
end
[~,scores] = model_select(Smodel,Next);   % 只对最后一代打分
```

`Next` 每轮被覆盖，**候选不累积**。`[Input(k); Ref.decs(k)]` = 2k 个父代 → 2k 个子代，k=6 时最终打分池只有 **12 个**。而且评价量不是 1 个：`sum(scores>3.9)<4` 时取 top-4，否则取全部 >3.9 的，即 **4~12 个**。

主算法的 [AdaMaOSelection.m:56-80](../../../Algorithms/Multi-objective%20optimization/REMO_new2_AdaMaO_SDEOnly_UniformMix_Original/private/AdaMaOSelection.m#L56-L80) 用 `all_candidates` 累积全部内循环产物。M=10 时 `k_eff=15`，每轮 30 个，约 96 轮 → **≈2990 个**。

$$|\text{pool}|: 12 \longrightarrow 3000$$

约 250 倍。**光是"从 3000 个里挑 6 个"而不是"从 12 个里挑 6 个"，就足以解释相当一部分 IGD 增益，与任何打分创新无关。**

### 2.2 V1 隔离这个因素

V1 用和 V2/V3/V4 **完全相同**的累积池，只是最终按 relation 分数取 top-6。于是：

| 对比 | 隔离出的因子 |
|---|---|
| V0 → V1 | 池化 + 阈值规则 |
| V1 → V2 | 模糊度 + 分散 |
| V1 → V3 | SDE 重排 |
| V1 → V4 | 两分支混合 |

**V1 不是 REMO**，它是一个比 REMO 强得多的基线。绝不能标成 "REMO-style controlled baseline"。

### 2.3 V1 不能沿用 3.9 阈值

得分上界是 4（`C_SCORE(1)` 最多累加 4 项概率，每项 ≤1）。在 3000 个候选里会有大量超过 3.9，批量会失控。所以 V1 用 top-`nMax`，代码在 [CVPCandidateSelection.m](../algorithms/private/CVPCandidateSelection.m) 的 `selectRelationTopK`。

注意出厂 `select_conservative` 取的是 `n_min`=4 而非 6，直接复用会引入批量差异。探针的 V1 统一用 `nMax`=6。

## 3. V0 的定位与其局限

V0 保留宿主的 HPC 标签和 `k_eff`，只换最终选择规则。这样"标签层"固定，V0→V1 才是干净的池化对照。

但 V0 的批量是 4~12 浮动，所以**V0 的任何对比都被批量混杂**。诊断表里 `v0_batch_mean` 报告实测值（冒烟实测 4.29）。论文里不要把 V0 当干净对照，真正的原版 REMO 基线是已有的两模块消融表。

### 顺带发现的一个 upstream 差异

原版 [REMO/RSurrogateAssistedSelection.m:117](../../../Algorithms/Multi-objective%20optimization/REMO/RSurrogateAssistedSelection.m#L117) 写的是：

```matlab
C_SCORE(1) = C_SCORE(1) + pre_XiC1(1);   % 注意是 XiC1
```

而 `REMO_new2/` 及后续所有版本写的是 `pre_XiC2(1)`。从上下文（该段处理 Xi 与 C2 的关系）看 `pre_XiC2(1)` 才是本意，原版那行是笔误。仓库里 21 份 `RSurrogateAssistedSelection.m` 只有 `REMO/` 这一份保留笔误版。

探针的 [CVPRelationScores.m](../algorithms/private/CVPRelationScores.m) 用 `d(1)`（即 `pre_XiC2(1)`），与主算法一致。**这意味着 V0 复现的是"修正后的打分 + 原文的选择规则"，不是逐字节的原文。** 这一点必须在论文里说清楚，否则 V0 会被误读成原文复现。

## 4. 单因子性如何保证

### 4.1 共享宿主

[CVP_CandidateProbe.m](../algorithms/CVP_CandidateProbe.m) 逐语句复制主算法的主循环：初始化、`HybridPBI_Classification`（同 `rGood`、同 `k_eff = min(N, max(6, ceil(1.5M)))`）、`GetRelationPairs`、`TrainOriginalRelationModel`、`IndicatorSelectorSDEOnly` + `fitrsvm`、`RefSelect(Archive, N)`。

唯一分岔点是 `CVPCandidateSelection(..., arm)`。

### 4.2 内层打分的刻意冻结

出厂代码的 `model_select` 内部按 mode 分岔（[AdaMaOSelection.m:337-349](../../../Algorithms/Multi-objective%20optimization/REMO_new2_AdaMaO_SDEOnly_UniformMix_Original/private/AdaMaOSelection.m#L337-L349)）：explore 用 `weighted_mean`（softmax 最大类概率为权），其他用普通 `mean`。

这意味着出厂的 Explore-only vs Rel-only 同时改了两件事：

- (a) 模糊度奖励 + 决策空间分散
- (b) **relation score 本身的聚合方式**

而 (b) 在原本的叙述里完全没提。若不处理，"Explore 有效"这个结论指向不明。

探针的处理：**内层 GA 父代打分对所有臂固定用简单平均**，保证候选池生成过程完全一致。代价被量化：`trace.GenerationAggregationChanged` 统计"如果不冻结，父代集合会变的轮次数"，汇总为 `aggregation_changed_fraction`（冒烟实测 **8.8%**）。写论文时正面报告这个数字。

最终选择阶段 explore 分支**仍然**用加权平均（保留出厂行为），由 `FinalAggregationWeighted` 字段记录。

### 4.3 配对随机性

[CVPStableSeed.m](../CVPStableSeed.m) = `problemIndex*10000 + M*100 + run`，**不含臂编号**。同一 `PairedKey` 的五个臂共享初始种群和全局随机流 → common random numbers → 配对 Wilcoxon 的效力显著高于独立运行。

`ResolveUniformMixMode` 的抽签走独立 RandStream（`CreateSDECandidateModeStream`，按 run 播种），不消耗全局流。oracle 的池子采样也走独立流（[CVPOracleStream.m](../algorithms/private/CVPOracleStream.m)，按 `(run, M)` 播种），**所以开关 oracle 不会扰动优化轨迹**，且各臂抽到同一子样本。

### 4.4 遮蔽风险的隔离

`platemo.m:79` 用 `addpath(genpath(cd))`。仓库里同名辅助函数的数量：

| 函数 | 非 private 副本数 |
|---|---|
| `RefSelect` | 37 |
| `GetOutput_PBI` | 32 |
| `DataProcess` | 32 |
| `onehotconv` | 32 |
| `GetRelationPairs` | 23 |
| `RSurrogateAssistedSelection` | 21（**7 种不同内容**） |

全会话只有一份胜出，取决于 `genpath` 的遍历顺序。这是 PlatEMO 的既有模式（stock 版 `EnvironmentalSelection.m` 有 145 份），但对需要精确复现的实验是隐患。

探针把冻结拷贝放进 `algorithms/private/`，MATLAB 从 `algorithms/` 调用时优先解析私有目录。[CVPSetupPaths.m](../CVPSetupPaths.m) 逐字节校验这些拷贝与出厂算法一致，不一致报 `CVP:FrozenTwinMismatch`。

## 5. CSR 的设计

### 5.1 用句柄身份

`SOLUTION` 是 handle 类（`Problems/SOLUTION.m:1`），`ALGORITHM` 也是。所以直接比较句柄：

```matlab
for index = 1:numel(NewSols)
    if any(Population == NewSols(index))
        survived = survived + 1;
    end
end
```

数值比较（`ismember(..., 'rows')`）在重复解上会误判 —— 而重复解确实存在（`countNearDuplicates` 在 CMC 实验里非零）。

### 5.2 世代混杂必须处理

`Problem.N = 100`，`Archive` 初始 100，maxFE=300 时最大 300：

| 世代 | `\|Archive\|/N` | CSR 的含义 |
|---|---|---|
| 1 | ≈1.0 | 几乎全员存活，**与选择器无关** |
| 末期 | ≤3.0 | 有一定选择压力 |

冒烟实测 `archive_over_n_max = 4.75`（smoke 用 N=20，比值更大）；formal 下约 3.0。

所以**绝不能报单个全程平均值**。三口径：

| 字段 | 计算 | 定位 |
|---|---|---|
| `SurvivalRateAll` | 全程 | 仅完整性 |
| `SurvivalRateLate` | `Ratio ≥ 0.50` | **主口径** |
| `SurvivalRateStage1..4` | FE 四分位 | 展示混杂 |
| `SurvivalRatePooled` | `Σ存活 / Σ评价` | 不受各代批量差异影响，V0 对比时更公平 |

`stage_profile.csv` 是专门给"CSR 是不是被世代污染"这个提问准备的。

实现在 [CVPSummarizeRun.m](../CVPSummarizeRun.m)。

## 6. Oracle 的设计

### 6.1 FE 中立性

[PROBLEM.m:136-158](../../../Problems/PROBLEM.m#L136) 里只有 `Evaluation` 累加 `obj.FE`：

```matlab
PopDec     = obj.CalDec(varargin{1});
PopObj     = obj.CalObj(PopDec);
...
obj.FE     = obj.FE + length(Population);
```

`CalObj` 和 `CalDec` 都是 public 且不动 `FE`。所以 `Problem.CalObj(Problem.CalDec(dec))` 完全离预算。单测 `testFEBudgetRespected` 守这条不变量。

Oracle 在**真实评价之前**运行（否则存档已被本批污染），且只在非 fallback 世代运行。

### 6.2 为什么是贪心批而非单点排序

单点口径（"按个体 ΔIGD 排 top-20%，看选中的落在里面几个"）会**系统性低估反冗余机制**：

设两个候选 `x1, x2` 都极好但彼此重合。单点口径给两个都记 hit；批次口径只值一个名额。用单点 oracle 评价一个刻意避免冗余的机制，等于用错误的尺子。

贪心批 oracle 与算法的批次目标对齐：

```
x1 = argmin_x C(A ∪ {x})
x2 = argmin_x C(A ∪ {x1, x})
```

### 6.3 覆盖度目标 C 与 IGD 的取舍

`C(S)` = 参考点到 `S` 中最近成员的平均距离，用**全集**。PlatEMO 的 IGD 用 `Population.best`（可行 + 非支配）。

| | 全集覆盖度 C | 前沿限制 IGD |
|---|---|---|
| 加点后单调 | ✅ 非增 | ❌ 新点可支配掉存档成员 |
| "最优批次"是否well-defined | ✅ | ❌ |
| 每次试算成本 | 一个距离向量 | 完整 NDSort |

贪心 oracle 需要单调性才well-posed，所以用 C。**论文的 IGD 主表仍用 PlatEMO 的 IGD**；C 只在诊断内部用，五臂完全一致，所以臂间比较是公平的。

这是一个刻意的、被记录的近似，不是疏忽。

### 6.4 成本控制

朴素实现：每代 3000 个候选、每步试算一次 IGD、6 步 → 每代约 18000 次 IGD，每次 IGD 是 `pdist2(10000×M, ...)`。不可行。

实际实现：

1. **一次** `pdist2(reference, poolObj)` 算出全部候选到参考点的距离矩阵，所有试算复用；
2. 每步试算退化为 `mean(min(currentMin, candidateDistance(:, remaining)), 1)` —— 一次向量化 min；
3. 参考集子采样到 300（定步长，保持铺满前沿）；
4. 池子采样到 400，**强制包含算法实际选中的全部候选**。

实测开销：M=10 单 job 350 s，关掉 oracle 305 s → **oracle 只占 13%**。大头是关系网络对 ~3000 候选打分。

`oracleEvery` 可以调（每 n 代跑一次），但因为开销只占 13%，formal 默认 `oracleEvery=1` 全代都跑。

### 6.5 子采样的解读约束

`oracle_subsampled_fraction` 为 1 时（formal 下必然），`HitRate` 的分母是"算法选中的候选数"，分子是与 oracle 批次的交集，但 **oracle 只在 400 个里搜索**。所以：

- 重合度对**算法的选择**是精确的（选中项全部在搜索空间内）；
- oracle 本身是 400 个里的最优，不是 3000 个里的最优。

读 HitRate 必须对照 `oracle_pool_considered_mean`。跨臂可比（同一子采样流），但绝对值不能解读为"在全池里的命中率"。

`OracleGainRatio = AlgorithmGain / OracleGain` 是 regret 式相对量，比裸 HitRate 更稳，建议作为主要 oracle 指标。

## 7. 一个副产品：批量恒定，多个参数是死代码

核对 explore 分支：`numel(cand_idx)` ≈ 3000×0.2 = 600，于是

```matlab
n_eval = min(nMax, max(nMin, 600)) = min(6, 600) = 6
```

indicator 分支同理恒为 6。所以：

| 事实 | 影响 |
|---|---|
| `\|S_t\| ≡ 6`（V1~V4） | `nMin=4` **永不生效** |
| indicator 分支的 `quantile(scores_ind, 0.70)` | **死代码**（过滤后仍取 top-6） |
| `qKeep` | 只对 explore 生效（定义 `diversity_select` 的候选池） |

诊断项 `batch_constant_non_v0` 确认这一点。写参数敏感性分析时不要说成"nMin 和 nMax 共同控制批量"。

### 7.1 因此 ΔIGD/FE 被排除

`|S_t| ≡ 6` 意味着 `ΔIGD/|S_t| = ΔIGD/6` —— 除以常数。而 `Σ_t ΔIGD_t` 是望远镜级数，等于 `IGD(P_0) − IGD(P_final)`，**和最终 IGD 是同一个数**。它不构成独立证据。

只在与 V0（批量 4~12 浮动）对比时才有信息量，此时可用 `SurvivalRatePooled` 承担类似作用。

### 7.2 Batch Diversity 只作 sanity check

acquisition 里显式加了 `0.25 × dist`，测出批内距离变大近乎恒真。`BatchSpreadNormalized` 证明"开关接通了"，**不证明"开关有用"**。已按决策变量的问题箱归一化（WFG 用 `upper = 2:2:2D`，DTLZ 用单位箱，不归一化不可比）。

## 8. 建议的补充测量（本探针未含）

`IndicatorModel` 是在 **100 样本、D 可达 30 维** 上训的 RBF-SVR，标签是**当代种群**的 SDE fitness，却要预测远离种群的候选 —— 外推。

建议单独测 holdout Kendall τ：

- τ 显著为正 → 可以讲 "indicator reranking"，故事成立；
- τ ≈ 0 → indicator 分支实质是对 relation top-30% 做**随机重排**。这仍可能有增益（打破 relation 的系统性偏好、正则化效应），但那是**另一个故事**，讲成"指标引导"会被抓。

这个测量很便宜却决定贡献 1 的措辞。本探针的 `v3_indicator_operational_fraction` 只回答"SVR 是否产生了有限预测"，**不回答"预测是否准确"**。

另一个零成本检查：桌面已有 `REMO_Candicate_10/20.xlsx`（UMC-only，用原版 `GetOutput_PBI`，无 HPC）。若 UMC-only 在 WFG3 上不退化，就支持"WFG3 退化归因于 HPC 的范数排序切前沿"，对候选模块升为贡献 1 是有用的辩护材料，且不用跑新实验。
