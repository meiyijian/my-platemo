# 候选解模块价值探针：实验结论

**数据范围：仅 M=20。** 200 个 job 全部完成（4 问题 × 5 臂 × 10 run），M=10 一个都没跑。本文所有结论都只在 M=20 下成立，可迁移性见第七节。

分析基于 `results/raw/formal/**/run_*.mat` 直接提取（MATLAB 的 `analyze_CandidateValueProbe('formal')` 未运行，7 张契约 CSV 不存在）。提取出的三张表在 [data/](data/)，字段与 `.mat` 中 `summary/`、`generations/` 逐一对应。

设计与操作见 [../README.md](../README.md) 与 [实验设计说明.md](实验设计说明.md)。**不含术语的简易版见 [实验结论_简易版.md](实验结论_简易版.md)。**

## 二、主结论：V4 ≈ V1，但这句话需要拆开说

按 IGD 均值（40 run 汇总）：

| 臂 | IGD | CSR(late) | CSR(pooled) | Oracle Hit(late) | GainRatio(late) | 批内分散 | 批量 |
|---|---|---|---|---|---|---|---|
| V0_REMO_RULE | 12.710 | 0.756 | 0.810 | 0.0149 | 0.123 | 1.806 | 10.39 |
| **V1_POOL_ONLY** | **10.627** | 0.706 | 0.769 | 0.0182 | 0.086 | 1.637 | 5.88 |
| V2_EXPLORE_ONLY | 11.445 | 0.677 | 0.748 | 0.0203 | 0.081 | 2.031 | 5.88 |
| V3_INDICATOR_ONLY | 14.588 | 0.761 | 0.822 | 0.0103 | 0.059 | 1.031 | 5.88 |
| V4_FULL | 10.973 | 0.770 | 0.826 | 0.0178 | 0.105 | 1.479 | 5.88 |

配对 Wilcoxon（40 对，common random numbers）：

| 对比 | 胜/40 | Wilcoxon p | 结论 |
|---|---|---|---|
| V4 vs V1 | 28 | **0.375** | 不显著 |
| V4 vs V0 | 27 | **0.008** | V4 显著优于 V0 |
| V4 vs V2 | 26 | 0.420 | 不显著 |
| V4 vs V3 | 24 | **0.004** | V4 显著优于 V3 |
| V2 vs V1 | 21 | 0.847 | 不显著 |
| V3 vs V1 | 20 | **0.027** | V3 显著**差于** V1 |

落在 README 第七节的第二个分支：**`V4 ≈ V1`，两者都 `> V0`（V1 vs V0 见第六节，实际不成立）**。按那张表的指引，"候选模块作主贡献"这条路走不通。

但这里有一个必须说清的细节。V4 vs V1 的**符号检验** p=0.017（28/40），而 Wilcoxon p=0.375。两者分歧说明：**V4 赢得更频繁，但输的时候输得更大。**分歧全部来自 DTLZ7。

| 问题 | V4 优于 V1 | V4−V1 均差 |
|---|---|---|
| DTLZ2 | **10/10** | −0.108 |
| WFG3 | **9/10** | −0.084 |
| WFG7 | 6/10 | −0.734 |
| DTLZ7 | **3/10** | **+2.311** |

剔除 DTLZ7 后：V4 优于 V1 **25/30，p=0.0026**。

所以诚实的表述是：**候选模块在 3 个问题上稳定小幅优于强基线 V1，在 DTLZ7 上大幅劣化，净效应抵消为零。**不要写成"V4 与 V1 无差别"（掩盖了 DTLZ7 的系统性劣化），也不要写成"V4 优于 V1"（只在剔除 DTLZ7 后成立）。

## 三、最强结论：CSR 是失效的代理指标，且失效方向可解释

这是本次实验信息量最大的一条，且是个干净的负结果。

**臂层面 CSR 与 IGD 几乎不相关。** 把 4 问题 × 5 臂 = 20 个单元各自在问题内排名后求秩相关（正值 = 该指标与 IGD 一致）：

| 指标 | 与 IGD 的秩相关 | p |
|---|---|---|
| `OracleHitRateLate` | **+0.706** | 0.0005 |
| `OracleGainRatioLate` | **+0.625** | 0.003 |
| `SurvivalRateLate` | +0.200 | 0.40 |
| `SurvivalRatePooled` | +0.096 | 0.69 |

**CSR 与批内分散度显著负相关。** run 层面按问题标准化后，`CSR ~ BatchSpread` 的秩相关为 **−0.314（p=6e-6）**；在 DTLZ7 上是 **−0.825**。

即：**批次挑得越挤，CSR 越高。**因为 `RefSelect` 保留的是靠近当前种群分布的解，而互相冗余的解一起靠近种群、一起存活。CSR 数的是"存活个数"，不区分这 6 个存活的解是 6 个不同方向还是 6 个几乎重复。

**CSR 最高的两个臂落在 IGD 的两端。** V4（CSR 0.770，第一）是 IGD 第二好，V3（CSR 0.761，第二）是 IGD 最差。两者 CSR 只差 0.009，IGD 差 3.6。**CSR 在最需要它区分的地方完全不区分。**

**V3 是失效机制的活证据：**它同时是 CSR 第二高（0.761）、批内分散最低（1.031，全臂最低）、IGD 最差（14.588，全臂最后）。在 DTLZ7 上尤其极端：

| DTLZ7 | V1 | V3 | 差异 |
|---|---|---|---|
| IGD | 17.364 | **32.509** | V3 **10/10 全败**，配对 Wilcoxon 原始 p=0.002 |
| CSR(late) | 0.732 | **0.937** | V3 9/10 胜，Cliff's δ=0.83 |
| 批内分散（late 世代口径） | 1.554 | **0.478** | V3 收紧到 1/3 |
| GainRatio | 0.187 | **0.066** | V3 显著更差 |

> 表中"批内分散"是 `FEBefore ≥ 150` 的世代级 `BatchSpreadNormalized` 均值。第二节主表用的是 run 级全程 `BatchSpreadMean`（DTLZ7 上 V1=1.611、V3=0.708）。两个口径都指向同一结论，但**引用时不要混用**。

逐 run 看，10 对里 V3 的 IGD 全部更差、CSR 全部更高（除 run 6）。这不是噪声。

**结论：CSR 不能作为候选质量的主指标写进论文。**如果写，必须与批内分散度一起报告，并明确说明 CSR 对冗余不敏感。审稿人只要问一句"高 CSR 是不是意味着选了一堆重复解"，单报 CSR 就没有答案。

设计文档第 5.2 节预见了世代混杂并给了三口径，这是对的；但真正的失效模式不是世代混杂，而是**冗余不敏感**。三口径解决不了这个问题——`SurvivalRatePooled` 的臂层面相关性（+0.096）比 `SurvivalRateLate`（+0.200）还低。

> 附带：`SurvivalRateStage1` 全 200 run 均为 NaN，且结构性必然。FE 从初始种群 100 起步、`maxFE=300`，所以 `FE/maxFE ≥ 0.333`，永远进不了第一四分位。四分位分箱应改为在 `[100, 300]` 区间内切，否则 `stage_profile.csv` 恒少一列。

## 四、Oracle 指标有效，但绝对水平低到需要正面交代

Oracle 两个指标的臂层面相关性（0.71 / 0.63）明显好于 CSR，方向也对。设计文档第 6.2 节选贪心批 oracle 而非单点排序，这个选择被数据支持——正是它捕捉到了 V3 的冗余问题。

但绝对水平很低，必须自己先说：

**命中率无一臂超过随机。** 考察池 400，V1–V4 批量恒 6，随机命中率 = 6/400 = **0.0150**；按 `mean(SelectedK / OraclePoolConsidered)` 在全臂上取均值为 **0.01554**（略高于 0.0150 是因为 V0 的批量更大）。下表用后者作基线，对 V1–V4 略偏保守。

| 臂 | Hit(late) | 相对随机 | p(>随机) |
|---|---|---|---|
| V2 | 0.0203 | 1.31× | 0.25 |
| V1 | 0.0182 | 1.17× | 0.21 |
| V4 | 0.0178 | 1.15× | 0.26 |
| V0 | 0.0149 | 0.96× | 0.88 |
| V3 | 0.0103 | 0.67× | 0.999 |

没有一臂显著优于随机；V3 显著**差于**随机。

**GainRatio 均值 0.059–0.123**，即各臂只拿到 oracle 批次覆盖度增益的 6%–12%，最好的单 run 也只到 0.55。

怎么解读这个组合（相关性有效、绝对值近随机）：**各臂选的批次和 oracle 的批次几乎不重叠，但"选得多差"这件事仍有区分度。**批次身份（选中哪 6 个）基本是随机的；批次质量（选中的这 6 个值多少）不是。所以 `GainRatio` 这个 regret 式连续量可以用，`HitRate` 这个离散量不能单独用——它在近随机区间里，方差主导。

设计文档第 6.5 节要求"读 HitRate 必须对照 `oracle_pool_considered_mean`"，这不够。**还必须对照随机基线 k/pool。**建议在 `diagnostics.csv` 里加一行 `oracle_chance_hit_rate`。

这也意味着因果链的中间环节实测很弱：候选选择策略 → 候选质量这一环，五个臂的差别远小于设计时的预期。

## 五、两个分支各自的裁决

**V3（indicator 分支）单独是有害的，不是中性的。** p=0.027 差于 V1，DTLZ7 上 10/10 全败，全局 IGD 最差。

这直接回答了设计文档第 8 节的担忧。那里的猜测是二选一：τ 显著为正则故事成立，τ≈0 则实质是随机重排、"仍可能有增益"。**实测是第三种情况：不是随机重排，是有系统性偏差的重排。**证据是批内分散度——随机重排不会把 run 级分散度从 V1 的 1.637 压到 1.031（DTLZ7 上压到 0.708）。SDE 代理在 D=30、100 样本上外推，产出的是一个**偏向局部聚集**的排序。

Kendall τ 那个测量现在优先级更高了：不是为了确认"有没有信号"，而是为了解释"偏差从哪来"。

**V2（explore 分支）单独无效，且是被自己的开关证伪的。** p=0.847，21/40。批内分散度确实从 1.637 上升到 2.031——开关接通了，机制在工作，但不转化为 IGD。

README 第八节说 `BatchSpreadNormalized` 只是 sanity check、"证明开关接通，不证明开关有用"。**这次数据把这句话变成了实测结论：开关接通了，确实没用。**

**混合的价值是抵消，不是叠加。** V4 显著优于 V3（p=0.004），不显著优于 V2（p=0.420），不显著优于 V1（p=0.375）。V4 的批内分散 1.479 落在 V2（2.031）和 V3（1.031）之间。

所以 `pMix=0.5` 干的事是**把 V3 的害稀释掉一半**，而不是把两个分支的好处加起来。这与 HPC 消融里"锚点数与混合表征是交互效应、不可加"是同一个模式：**模块组合的收益不是各模块单独收益之和，单独测有害的模块在混合里可以不害。**这个模式出现两次了，值得作为一个方法学观察单独写——它同时也是"为什么必须做单因子消融"的正面论据。

## 六、备选叙述也不成立：累积池不是全局有效的

README 第七节给的退路是"若 V4 ≈ V1，真正贡献是累积候选池，换叙述"。这条退路在 M=20 下**同样不成立**。

V1 vs V0（池化 + 阈值 → 池化 + top-6）：**17/40，p=0.599**，全局不显著。

| 问题 | V1 优于 V0 | 均差 | p |
|---|---|---|---|
| DTLZ7 | **9/10** | −8.774 | **0.004** |
| DTLZ2 | 4/10 | +0.013 | 0.770 |
| WFG7 | 4/10 | +0.275 | 0.432 |
| WFG3 | **0/10** | +0.151 | **0.002** |

池化在 DTLZ7 上是大幅正收益（12→3000 的池确实帮到了断开前沿），在 WFG3 上是显著负收益，其余两个问题打平。**"从 3000 里挑 6 个"不是普遍优于"从 12 里挑 6 个"。**

需要注意 V1 vs V0 被批量混杂，且比设计文档预计的严重。V0 实测批量均值 **10.39**（设计文档记录的 4.29 是 smoke 值，N=20），且随问题剧烈变化：WFG7 4.76、WFG3 8.88、DTLZ2 12.00、DTLZ7 15.90。世代数也随之变化（16.2–42.1，而 V1–V4 恒 34）。所以 V0 的每一项对比都同时混杂了批量、世代数和选择规则，**三者不可分离**。README 第二节说"不要在论文里把 V0 当作干净对照"，实测支持这个警告，且程度比预期更重。

## 七、WFG3 可falsify案例：结果对现有叙述不利

README 第七节把 WFG3 设为可falsify案例，期望的辩护是"若候选模块在 WFG3 上不退化，就支持 WFG3 的退化归因于 HPC 的范数排序切前沿"。

实测：**V1 在 WFG3 上 10/10 差于 V0，p=0.002。**候选模块的池化部分在 WFG3 上自己就退化，与 HPC 无关（V0 和 V1 共享同一套 HPC 标签和 `k_eff`）。

所以**这个辩护材料不成立**。WFG3 的退化至少有两个独立来源：HPC 的范数排序（已有消融表），以及累积池化本身。

一个反向的观察：WFG3 上表现最好的是 V3（2.695），而 V3 是全局最差的臂。V3 在 WFG3 上批内分散 1.423（它在其他问题上是 0.478–0.940），收紧程度最轻。在退化前沿上收紧批次反而对——这与"退化前沿需要的是沿前沿方向密集采样而非分散"是一致的，可以作为一个机制假说，但 n=1 个问题，不要当结论写。

## 八、可迁移性与需要补跑的部分

**只有 M=20。**哪些结论可能随 M 变化：

| 结论 | 对 M 的敏感性 | 理由 |
|---|---|---|
| CSR 冗余不敏感（第三节） | **低** | 机制性的，来自 `RefSelect` 的分布偏好与 CSR 的计数定义，与 M 无关 |
| Hit rate 近随机（第四节） | **低** | 6/400 的随机基线与 M 无关；池规模在 M=10/20 下都约 3000 |
| V4 ≈ V1（第二节） | **高** | 已有 HPC 消融显示 M=10 与 M=20 的模块贡献不同；`k_eff` 从 30 变 15 直接改变内循环产出 |
| V3 有害（第五节） | **中** | SDE 代理的外推难度随 M 上升，M=10 下可能没这么差 |
| 池化非普遍有效（第六节） | **中高** | V0 的批量在 M=10 下不同（`k_eff=15`），混杂结构会变 |

按信息量排序的补跑建议：

1. **DTLZ7 M=10 全 5 臂**（50 job，约 4.8 h）。DTLZ7 是所有分歧的来源——V1 在这里大胜、V3 在这里惨败、V4 的净效应在这里被抵消。M=10 下这个问题的行为决定第二节和第五节要怎么写。
2. **WFG3 M=10 全 5 臂**（50 job）。第七节的结论直接影响 HPC 归因的辩护，需要第二个 M 确认。
3. **indicator 代理的 holdout Kendall τ**（设计文档第 8 节，几乎零成本）。现在它的优先级高于补跑——第五节已经证明 V3 有系统性偏差，τ 是解释偏差来源的唯一手段。
4. 其余 M=10（DTLZ2、WFG7），补完整性。

如果机时紧张，**3 优先于 1**。

## 十、一句话总结

候选解模块在 M=20 下相对强基线 V1 **净效应为零**（3 个问题小胜、DTLZ7 大败）；其两个分支单独测都不成立（explore 无效、indicator 有害），混合的作用是抵消而非叠加；备选的"累积池是真正贡献"叙述同样不成立（池化在 WFG3 上显著有害）。

方法学上的收获比算法收获大：**CSR 这个指标被证伪了**（奖励冗余，臂层面与 IGD 不相关），oracle 命中率在随机区间内，只有 regret 式的 `GainRatio` 可用。这三条都是可以正面写进论文的负结果，且都是设计文档预留的失效模式被实测击中——探针本身是有效的，被证伪的是它测量的机制。
