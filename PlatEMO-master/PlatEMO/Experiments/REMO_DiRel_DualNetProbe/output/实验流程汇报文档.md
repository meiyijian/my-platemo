# REMO_DiRel 双网络探针实验 —— 流程与实现说明（汇报版）

> 目标读者：导师。本文用尽量直白的语言介绍：**这个实验为什么做、怎么做、用什么实现、结果怎么看**。

---

## 一、要回答的问题（实验动机）

REMO_DiRel 算法里有一个关键设计：**"双网络代理"**。

- **F 网络（全目标网络）**：用所有 M 个目标的 Pareto 支配关系训练一个打分网络。
- **S 网络（子目标网络）**：只在一组"易子目标 `S_easy`"上训练另一个打分网络。
- **逆方差融合**：把两个网络的预测按各自的不确定度加权融合，得到候选解的最终得分。

但是这个双网络结构**是否真的有用**，目前是一个黑盒。我们想搞清楚：

1. 两个网络的预测**有多大比例会"打架"（异号）**？
2. 单看每个网络，**预测的准确率**有多高？
3. 当两个网络打架时，**到底谁更可信**？
4. **融合权重 `w_F`** 是否真的把权重交给了更准的那个？
5. 根据这些结果，应该用**分阶段策略**、**自适应加权**、还是**保持现状**？

为了回答上面的问题，我们没有改算法，而是给算法**加了一个"探针"（Probe）**，把每一代每一个候选解被双网络评分的全部中间数据都录下来事后分析。

## 二、实验流程（白话版）

整个实验分**"跑实验 → 离线分析 → 出图表"** 三步。

```

│  run_dualnet_experiment.m                                    │
│    └─ 调用 platemo(...) 跑 REMO_DiRel_dualProbe              │
│         └─ 每一代：双网络打分 + 真实评估 + 录到 .mat 文件     │
│             (compute_dualnet_metrics.m)                      │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼  results/*.mat（每个 run 一个）
┌──────────────────────────────────────────────────────────────┐
│  Step 2: 离线分析                                             │

┌──────────────────────────────────────────────────────────────┐

```

### 2.1 实验设置（"撒了多少种子"）

来源：[run_dualnet_experiment.m:11-19](../run_dualnet_experiment.m#L11-L19)

| 维度                       | 取值                                      |
| -------------------------- | ----------------------------------------- |
| 测试问题                   | DTLZ2、DTLZ3（多目标基准问题）            |
| 目标维度 M                 | 5、10、15（覆盖中、高、超高维）           |
| 决策维度 D                 | 10（M=5）、19（M=10）、24（M=15）         |
| 每个配置独立运行次数       | 10 次（消除随机性）                       |
| 单次实验真实评估上限 maxFE | 500（昂贵优化的典型设定）                 |
| 一共                       | 6 配置 × 10 run =**60 次完整运行** |

> "昂贵优化"指真实目标函数评估代价很高（比如要做 CFD 仿真），所以 maxFE 才设 500。

### 2.2 算法每一代发生的事（这是核心）

实现在 [REMO_DiRel_dualProbe.m:46-153](../REMO_DiRel_dualProbe.m#L46-L153)。每一代算法做了这 8 件事：

1. **挑参考解 Ref**：从当前种群里选 6 个代表性的点，作为后续 PBI 分类的"锚"。
2. **判断哪些目标是"易子目标"**：调用 `DifficultyProfiler`，根据历史代数对每个目标维度评一个难度分，挑出最"好学"的 `k_easy` 个目标组成 `S_easy`。
3. **打 F 标签**：在全 M 目标空间做 PBI 分类，每个解被打成"保留 (1)" 或 "剔除 (0)" → 得到训练标签 `Catalog_F`。
4. **打 S 标签**：只在 `S_easy` 这几个子目标上做 PBI 分类 → 得到 `Catalog_S`。
5. **训练双网络**：`TrainDualScaleNet` 用 F 标签训出 `nets_F`，用 S 标签训出 `nets_S`。每个网络都是一个**集成**（K_ens=3 个子网络），有集成方差作为不确定度。
6. **🔬 探针采样**：用遗传算子 `OperatorGA` 生成约 50 个候选解，对它们做下面的事 —— **这一步不影响算法，只用于记录数据**。
7. **🔬 探针计算（compute_dualnet_metrics.m）**：
   - 用 F 网络给每个候选打分：得到 `mu_F`、`sigma2_F`。
   - 用 S 网络给每个候选打分：得到 `mu_S`、`sigma2_S`。
   - 计算融合权重 `w_F = (1/σ_F²) / (1/σ_F² + 1/σ_S²)`。
   - 计算融合得分 `base = w_F·tildeS_F + w_S·tildeS_S`。
   - 判定**冲突类型**：`agree`/`conflict`/`abstain`/`subwin`。
   - **旁路调用 `Problem.CalObj`** 直接算出候选解的真实目标值（不计入 FE），然后和当前种群做 Pareto 支配判定，得到 `true_quality`（这是"金标准"）。
   - 把所有数据存进 `rec` 结构体。
8. **算法正常往前走**：用真正的 `ArbitratedSelection` 选出下一代要评估的解，调用 `Problem.Evaluation` 消耗 FE。

> **关键的"作弊但合法"**：第 7 步的"旁路评估"用 `Problem.CalObj` 算真实目标值，但**不增加 `Problem.FE` 计数**。这是离线诊断的合法用法 —— 我们不是在帮算法选解，只是在"事后判卷"看双网络猜得对不对。

### 2.3 一次实验落盘的产物

每跑完一次 run，[REMO_DiRel_dualProbe.m:131-132](../REMO_DiRel_dualProbe.m#L131-L132) 会把所有探针数据存成一个 `.mat`：

```
results/dualnet_DTLZ2_M5_run1.mat
results/dualnet_DTLZ2_M5_run2.mat
...（共 60 个）
```

每个 `.mat` 里包含两个数组：

- `gen_data{i}`：第 i 代的汇总（哪些目标是易目标、训练误差等）。
- `probe_data{i}`：第 i 代每个候选解的全套打分和真实标签。

## 三、离线分析（怎么从 60 个 .mat 变成可读结果）

入口：[analyze_dualnet_results.m](../analyze_dualnet_results.m)。

它做了 4 件事：

### 3.1 把 60 个 .mat 摊平成两张大表

- `per_generation_summary.csv`：每行 = (问题, M, run, 代数)
- `per_candidate_detail.csv`：每行 = (问题, M, run, 代数, 候选编号)，最细粒度

### 3.2 按问题聚合成对比表

- `cross_problem_summary.csv`：每行 = (问题, M)，把所有 run × gen × 候选 聚成一行。**一眼看哪个问题/M 上双网络分歧最大、谁更准**。

### 3.3 按冲突类型切片

- `conflict_analysis.csv`：每行 = (问题, M, 冲突类型)。**直接告诉你 `subwin` 时 S 是不是真的赢了**。

### 3.4 出图

按问题画 5 张图，再画 1 张跨问题对比图，共 6 类图：

- μ_F vs μ_S 散点（按冲突类型着色）
- 各项指标随代数变化曲线
- w_F 分布直方图
- 冲突场景下的准确率柱状图
- 选择重叠/选择质量
- 跨问题汇总柱状图

详细字段含义见同目录下 [CSV_指标说明文档.md](./CSV_指标说明文档.md)。

## 四、用到的关键技术点（万一被追问）

| 技术                                  | 出处                                                                 | 一句话解释                                                                |
| ------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **集成网络 + 集成方差**         | `TrainDualScaleNet`，K_ens=3                                       | 训练 3 个小网络，预测均值作 μ，预测方差作 σ²（不确定度估计的廉价做法） |
| **逆方差融合**                  | [compute_dualnet_metrics.m:67-72](../compute_dualnet_metrics.m#L67-L72) | 谁更"自信"（σ²小）就给谁更高权重，理论最优融合                          |
| **PBI 分类**                    | `GetOutput_PBI`                                                    | 用一个角度阈值把种群切成"保留/剔除"两类，等价于生成支配关系的二分类标签   |
| **难度画像 DifficultyProfiler** | 每代调用一次                                                         | 看哪些目标维度学得快/好，自动挑出易子目标                                 |
| **旁路真实评估**                | [compute_dualnet_metrics.m:89-98](../compute_dualnet_metrics.m#L89-L98) | 调 `Problem.CalObj` 但不计 FE，得到 ground truth 用于事后判分           |
| **NN baseline**                 | 用决策空间最近邻假装真实值                                           | 对照用：如果不能旁路真实评估，最近邻估计会差多少                          |

## 五、当前已经得到的主要观察（从已生成的 CSV 直接读）

数据来源：[output/cross_problem_summary.csv](./cross_problem_summary.csv) 和 [output/conflict_analysis.csv](./conflict_analysis.csv)。

1. **两网络分歧很普遍**：DTLZ2 上冲突率 ~51%，DTLZ3 上甚至 ~59%（M=10），不是个别现象。
2. **F、S 单独看准确率都不高**（55% 左右，比随机猜略好），说明**任一网络单独用都不够**。
3. **冲突时 F 略优于 S**（如 DTLZ2 M=10：F 在 conflict 子集 0.65 vs S 0.35）—— 但**`subwin` 子集里 S 反而显著更准**（0.78 vs 0.22），说明现在的 arbitrator 路由方向是对的。
4. **真实评估几乎全部成功** (`has_real_obj_pct = 100%`)，结论可信。
5. **NN baseline 误差不小**：`label_agree_real_nn_mean` 在 0.59~0.86 之间 —— 强烈说明这个实验必须做真实评估旁路，否则会被 NN 误差污染。

> 这 5 条结论已经够支撑后续改进方向的讨论了（例如：是不是该把 arbitrator 的 `subwin` 触发条件再放宽一点？或者按冲突率自适应调整 F/S 权重？）。

## 六、跑这套实验需要做的操作

```matlab
% 第一步：进入实验目录
cd PlatEMO/Experiments/REMO_DiRel_DualNetProbe

% 第二步：跑完整实验（约 1-2 小时）
run_dualnet_experiment

% 第三步：分析、出 CSV、画图
analyze_dualnet_results
```

中途断电没关系：[run_dualnet_experiment.m:49-52](../run_dualnet_experiment.m#L49-L52) 会自动跳过已经存在的 `.mat`，下次继续从断点跑。

## 七、汇报时的一句话总结

> "我没有改 REMO_DiRel 的算法逻辑，而是给它加了一个**探针**：每一代用真实目标函数旁路评估 50 个候选解，记下两个代理网络分别给出的预测、方差、融合权重，再和真实 Pareto 支配关系对比，最后产出 4 个 CSV 和 6 类图。这样就能定量回答 **双网络到底有没有用、什么时候打架、打架时谁说了算、融合权重分得对不对**，为后续改进 arbitrator 提供数据支撑。"
