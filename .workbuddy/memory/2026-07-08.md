# 2026-07-08 WFG10 性能提升来源分析

任务：分析 REMO_new2_WFG10 相对 REMO_new2 的性能提升来源（用户计划后续对 AdaMao 做消融实验，担心模块臃肿、超参数多不利于发文章）。

## WFG10 相对 new2 的三处改动
1. 置信度加权关系对训练（GetRelationPairs_confidence + DataProcess_confidence + EW 权重）
2. 自适应参考解数量 k_eff = min(N, max(k, ceil(1.5*M)))，10 目标时 6→15
3. 不确定性/多样性感知候选选择（分位数 + unc + 贪心多样性，替换固定阈值 3.9）

## 代码层关键事实
- 最终环境选择 RefSelect(Archive, Problem.N) 用 k=N，小 k 只影响 HPC 内部 Ref 与 GA 种子，不影响最终种群多样性。
- k_eff 多通道杠杆：① label_dyn（GetOutput_PBI 用 k 个 Ref 做局部 PBI 标签，粒度更细）② Ref.decs 作 GA 种子 ③ 内层 keepNum=length(Ref) 精英父代池更大。
- 基线候选选择固定阈值 3.9 是低维调参，高维下分数分布不同，基本退化为 top-4，无多样性。

## 假设排名（待消融验证）
- 主导：A (k_eff) — 结构性修正，提升标签质量（关系学习数据根基）+ 多样性种子。
- 次：B (不确定/多样选择) — 修正脆弱阈值、避免聚簇浪费昂贵评估预算。
- 最小：C (置信度加权) — 仅调训练权重，温和；AdaMaO 常回退到无加权 conservative 且性能不降（消融报告佐证）。

## 根因判断
WFG10 提升主要来自「修正 new2 低维→高维(10目标)失配」，非新机制。与 AdaMao 消融报告一致（指标子系统等新增模块无显著差异；Full≈WFG10）。

## 发文章策略讨论（用户目标：一区 Swarm and Evolutionary Computation）
- 用户担忧：若 A(k_eff) 主导，则贡献退化成"给 REMO 做超参分析"，恐难发表。
- 我的判断：① A 主导仍是假设，未消融验证；② 即使 A 主导，"维度自适应、去手工调参的参考机制"本身是方法贡献，非单纯超参分析；③ 用户其实有两个自适应参考机制（k_eff 参考解数 + AdaptiveReferenceVectors K-means 参考向量场），不是"一个作用不大"。
- 真正风险是叙事（"REMO+小修"）与借来的 PIEA/课程学习模块污染，而非贡献大小。
- 出路：先跑单因子消融定事实；再整体框定为"expensive many-objective 下的 regime-adaptation 关系学习框架"，把自适应参考机制立为卖点；删掉 borrowed 模块；补 M=5/15 与 HV。
