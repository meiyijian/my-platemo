### 新增护栏：确定性卡死 run 的"投毒"机制
种子固定（`22260912+1000×题号+run`）⇒ **卡死的 run 重驱必定再卡**，旧 driver 会在一个槽位上
反复烧满 `SLICE_TIMEOUT`（8 轮 × 4 h），扫描永不收敛。做法：driver 记每个切片的退出码
（`logs/<KEY>/rc_part<NN>.txt`，`<runs>|<rc>`）；`timeout` 杀进程返回 **124**；
同一片同一 run 列表被 124 杀 **≥2 次** → `mark_poison.py` 把**列表里第一个磁盘上没有 .mat 的 run**
写进 `logs/<KEY>/poison.txt`（切片按序执行且完成的 run 都原子落盘，所以第一个缺的就是卡死的那个，
它后面的只是没轮到）；`missing_runs.py` 据 `FE500_POISON` 跳过这些对；driver 收尾记 `poisoned=<n>`；
**验收脚本会把这些缺口报成 MISSING，不会被悄悄吞掉**。要求 2 次是为了不把"只是慢"误判成卡死。
